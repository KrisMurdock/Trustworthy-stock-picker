# stock_watcher

原生 Go 的 A 股龙头股池日线监控与短线排名研究。服务器下载历史日线，直接写入 Windows 共享盘；收盘后生成下一交易日的观察排名或候选股，并通过飞书自定义机器人推送。启动、下载、筛选、回测和推送均由 Go 程序执行。

## 运行

需要 Linux、Go 1.26 和已经挂载的 CIFS 共享。服务器上的 `data` 链接到 `/mnt/windows_database`，对应 Windows `D:\shared_database`。默认拒绝本地磁盘回退，Windows 关机或 SSH 隧道断开时不会改写服务器磁盘。

```bash
make build
cp config.yaml.example config.yaml
chmod 600 config.yaml
./bin/stock-watcher init -config config.yaml
./bin/stock-watcher check -config config.yaml
./bin/stock-watcher sync -config config.yaml
./bin/stock-watcher preview -config config.yaml -as-of 2026-10-13
./bin/stock-watcher run -config config.yaml
```

`make run` 构建后前台运行，启动即按北京时间确定最近已收盘交易日，重新同步整个股池、保存到配置的数据目录、分析并尝试推送飞书。即使当天已有报告也会重新下载；默认下载前复权分析窗口和至少十年的不复权日线；未启用短线策略也会保存原始历史。完成后持续运行，按 `daily.run_at`（默认 18:05）处理后续交易日。

- 交易日 15:00 前使用上一已收盘交易日；周末和节假日跳过休市日。盘中启动会更新数据与分析，但目标买入日已到 09:30 的旧推荐不再推送。收盘后启动立即处理当天，无需等待 18:05。
- 全池同步失败时不发送缓存报告，按轮询间隔重试（至少 1 分钟）。飞书发送失败后只重试投递，不重新下载整池；权限或签名错误仍需修正后用 `retry` 解锁。
- 每个数据日期、每个通道保留首次投递记录。同日重启或修改配置会更新本地报告，但不会重复推送已送达消息，也不会替换待重试的消息快照。新增通道可接收当日尚未过期的报告。

`sync` 只下载并生成报告，不发送消息。`once` 只执行一次定时调度，遵循 18:05 和开盘前补发窗口，不执行启动强制同步。`status` 查看投递状态，`retry [channel]` 在停止服务并修正永久错误后解除指定通道或全部通道的阻塞。修改配置或股池后重启生效。启动日志显示日期、同步进度和入队通道数；未推送时记录原因（未启用通道、已过买入时点或已有投递记录）。

`leaders.yaml` 保存已核对的 104 个证券代码和名称，可直接添加或删除股票。用户原名单另外 6 个疑似笔误在 `leaders.pending.yaml`，确认前不参与下载与筛选。上海和深圳 A 股支持带市场前缀的代码；名称不会参与自动猜测。维护者应使用已核对的证券代码。上市不足 10 年的股票必须在股票配置中填写已核实的 `listed_from: YYYY-MM-DD`，同步保存上市日起的全部可用日线；缺少该声明时会报历史覆盖不足，不会把短数据误认为完整十年。`cmd/resolve-pool` 可辅助核对名称，结果须人工检查。

## 短线净收益排名

在配置中设置 `strategy.schema_version: 1` 和 `strategy.enabled: true`，启用新的全池排名。默认保持旧配置的趋势筛选行为，启用后需先运行 `sync` 更新分析报告与不复权日线：

```bash
./bin/stock-watcher sync -config config.yaml -as-of 2026-10-13
./bin/stock-watcher preview -config config.yaml -as-of 2026-10-13
./bin/stock-watcher research -config config.yaml -as-of 2026-10-13
./bin/stock-watcher plan -config config.yaml -code sz000001 -entry-price 10
```

`preview` 输出全池排名和研究结果，`research` 仅输出研究统计，二者只读 Windows 行情、不发消息。`plan` 按输入成交价和配置预算计算买入数量、买入总成本、净 +2.5% / +3% 卖价及净止损价，不需要访问行情盘；输出数量是预算推算，使用前核对实际成交数量和费用。预选报告中的计划以当日不复权收盘价估算，标记 `reference_only: true`；它不是次日已知买入价或买入指令。

首版交易假设：

- 信号日收盘后排名，下一个交易日开盘价加单边滑点买入；开盘相对前收盘偏离超过 3%、无成交、平价一字板或预算不足时不模拟买入。
- 主目标为扣除买卖费用后的 **+3%**，并单独统计 **+2.5%**；净止损 **-3%**。最早卖出日在买入后的下一个交易日，默认买入后第 **5** 个交易日收盘到期退出，同时比较 1 / 3 / 5 日窗口。5 日是首版研究参数，不代表已验证的最佳持有期。
- 用户佣金按双边 **万一**。每只预算 **2 万元**、最低佣金 **5 元**、单边滑点 **0.05%** 暂作假设，可在 `strategy` 中修改。按配置计入双边过户费和卖出印花税；默认费率分别为 0.001% 和 0.05%，参考[上交所股票投资指南](https://one.sse.com.cn/onething/gptz/)。佣金假定已包含券商收取的交易经手费用，不再重复加收。
- 买入预算包含买入费用；主板/创业板按 100 股整手，科创板最低 200 股、之后按 1 股递增。卖出目标向上取到分，止损向下取到分。触价不等于成交：止盈需日内最高价越过目标至少一分钱；同日同时触及止盈/止损且开盘未决定顺序时，按先止损处理。跳空会按开盘及滑点模拟，亏损可能超过 -3%。一字跌停和缺失交易日不虚构退出。

特征复用现有均线、MACD、RSI、量比与趋势评分，并增加 1 / 5 / 10 日收益、20 日均线斜率与偏离、ATR14、收盘位置、上影线、距前 20 日高点及相对股池强度。固定规则包括放量突破、趋势回踩、相对强势和放量转强。所有可用股票都有机会分和稳定排名，历史不足、停牌和 ST 等列为排除项；高排名不自动等于推荐。

特征使用前复权价格，成交模拟使用独立下载的不复权价格。每个历史信号只用当时及之前的价格特征；规则证据只能来自完整持有窗口已经结束的样本，边界重叠样本被剔除。开发区间逐日更新历史证据，最近 40 个完整信号日作为验证区间，区间内固定证据。统计分别列出全池、前 N 名、通过门槛的前 N 名和旧趋势规则，包含买入跳过数、净目标达标率、已退出平均净收益、止损/超时/未解样本及单笔风险边界。

推荐需要至少 60 个买入样本、40 个不同信号日、正的平均净收益、优于全池的达标率，以及机会分和波动门槛；尚有无法确定结果的规则不会通过。独立验证区间还须有至少 30 个通过门槛的买入样本、10 个信号日、没有未解样本，平均净收益为正且收益和达标率均优于全池。未通过时照常生成观察排名，飞书明确说明没有股票满足推荐门槛。统计门槛是筛选条件，不是对未来收益的承诺。

研究仍有明确局限：使用当前龙头池回看历史，有选股与幸存者偏差；没有历史 ST/IPO 状态和盘口成交顺序；前复权数据是当前快照，除权窗口保留为未解样本；不同股票与持有窗口会重叠，因此平均收益不是实盘组合收益、机会分不是上涨概率。按信号日数量限制样本量的 Wilson 下界仅作排名保守项，不是经过校准的置信区间。MAE/MFE 是包含退出日整根日线的风险边界，可能包含模拟退出之后的价格，不能当作分钟级真实持仓回撤。

## 旧趋势筛选条件

条件全部满足后，按现有技术趋势评分降序取前 5 名，分数相同时按证券代码排序：

- 收盘价 > MA20，且 MA5 > MA10 > MA20。
- 今日成交量 / 前 5 个交易日平均成交量 ≥ 1.2，且 MACD DIF > DEA。
- RSI14 在 50～80，单日涨跌幅在 -3%～7%，总分至少 70。
- 排除 ST、退市标记、无成交量、当日数据未更新及不足 35 根日线的股票。

评分延续旧代码的均线 30 分、MACD 25 分、RSI 20 分、连涨 15 分、量比 10 分。修正旧 RSI 最后一根的平滑计算；量比使用同一返回序列的成交量原值，不把成交额当成交量。MA、MACD、RSI 使用同一窗口的前复权价格。默认重新下载最近 365 个自然日的完整窗口，避免把不同日期复权基准的数据拼在一起。阈值、Top N、历史范围和时间均可配置。这是透明的技术规则筛选，尚未经过收益回测。

没有股票通过时，报告和飞书明确显示“没有满足筛选规则的股票”。过期、停牌和数据不足单独列出；单票永久数据错误会隔离并告警，临时网络、共享盘和事务错误会阻止本轮发布，覆盖率达到门槛后才生成报告。

## 股池网页

执行 `make run` 会同时启动日线监控和只读网页，浏览器打开 `http://127.0.0.1:8080`。页面资源嵌入 Go 二进制，无需安装 Node 或单独启动前端。首次部署仍需先运行 `stock-watcher init -config config.yaml`。

网页监听成功后，终端会明确打印 `Dashboard ready at http://127.0.0.1:8080/`，地址随实际配置端口变化。默认地址指服务器本机；在 Windows 浏览器访问时，先建立 SSH 端口转发。监听 `0.0.0.0` 或 `::` 时，日志展示对应本机访问地址，并在 `listen` 字段保留真实监听地址。

页面展示配置股池中的全部股票，包括缺失或被排除的数据，支持名称/代码搜索、行业与数据状态筛选及排序。「已同步数据」卡片中的「查看已同步股票」可直接筛出有行情的股票。摘要包含已完成交易日、快照生成时间、覆盖率和筛选数量；每日排名读取已保存报告，可切换历史日期。短周期策略展示完整观察排名与推荐状态，旧趋势策略展示已保存的筛选排名。这里展示的是日线快照，不是实时行情，历史排名也不会用新行情重新计算。

点击导航中的「仓位计算」或直接打开 `http://127.0.0.1:8080/calculator`，可输入账户资金、亏损预算、止损价与买入计划，测算底仓和加仓数量、剩余风险及净止盈价。支持多批已有持仓、固定净利润金额或收益率目标，默认净收益率 3%。计算仅在浏览器内进行，不上传或持久化账户金额，也不依赖行情接口；刷新后清空参数。公式与命令行脚本一致，使用说明见 [单股价格策略](docs/单股价格策略.md)。

点击导航「个股 K 线」、股池或排名中的股票名称，或使用图表的股票选择框，可查看日 K、成交量和 MA5/10/20。支持最近 60 根、120 根、250 根与全部已保存日线；悬停、点击图中日期或拖动下方滑块可查看开高低收和均线数值。均线先按完整已保存窗口计算，再截取显示范围；不足周期的数值显示横线。价格口径默认使用配置的复权分析窗口，可切换「不复权 · 原始历史」查看本地留存的十年原始日线；标题下明确显示实际保存的起止日期与根数，不足十年不会补造数据。长历史按可读的蜡烛宽度横向滚动，拖动日期滑块会定位到对应 K 线。复权与不复权价格独立读取，不混用不同窗口；不复权价格可能出现除权除息跳空，成交量保留数据源原始单位。

股池下载完成但覆盖率不足时，通过校验的行情和隔离原因仍会事务落库，网页可读；默认 95% 的推荐门槛不变，本轮不会创建推荐或发送通知。页面明确区分行情日期与报告日期，旧报告仍可回看，但不会把旧入选状态套到新行情上。切换到数据缺失的股票时清空图表并说明原因，不回退展示旧日线。临时网络失败导致下载未完成、共享盘异常或事务失败时，仍保留此前数据并等待重试。

网页先启动，监控随后同步；首次没有快照时显示等待同步，读取失败时显示错误和重试入口。浏览器每分钟刷新一次，刷新不会触发行情下载或消息推送。所有网页接口只读，不提供账号、配置修改或交易操作。`GET /api/history?code=sz000001` 返回当前股池股票的最新已校验日线窗口（`schema_version: 1`，最多 6000 根），缺失/隔离或不在股池返回 404；可追加 `&adjust=none` 读取不复权历史；`adjust` 仅接受当前配置口径或 `none`，不接受任意日期及其他参数。`/api/dashboard` 的 `report_current` 标记报告是否对应当前行情。

监听地址可通过 `web.listen` 或 `STOCK_WATCHER_WEB_ADDR` 设置，例如 `STOCK_WATCHER_WEB_ADDR=127.0.0.1:8088 make run`；`web.enabled: false` 关闭网页。默认仅本机可访问。容器内部监听 8080，Compose 默认映射到宿主机 `127.0.0.1:8080`，其他端口可设置 `STOCK_WATCHER_WEB_BIND`。远程访问需受控网络或已有认证反向代理；代理应保留根路径、`/api/` 和 `/assets/`。

## Windows 文件

```text
data/                       # 实际位于 Windows 共享盘
  market.db                 # SQLite 主数据文件；首次部署由 init 显式创建
  state/delivery.json
  .stock-watcher.lock
logs/stock-watcher.log       # 服务器上的有限运行日志
```

先执行 `./bin/stock-watcher init -config config.yaml` 创建 `market.db`，再运行 `sync` 或 `run`。普通写入模式不会自动创建数据库，避免共享盘挂载错误时误写到错误位置。行情日线、复权/不复权窗口、同步状态和覆盖率通过 SQLite 事务保存；达到推荐覆盖率门槛时，与筛选报告在同一事务中发布，否则只保存有效行情及本轮未通过覆盖率的状态。事务失败时保留此前完整数据。`preview`、`research` 和 `status` 使用只读连接。旧版 `daily/`、`execution/` 和 `reports/` JSON 仅作为数据库不存在时的只读兼容回退，新的 CLI 生产路径不再写入这些行情 JSON。

每次同步都会保存截止日前至少 **10 个自然年**的**不复权原始日线**，无论是否启用短线策略。`daily.history_days` 继续控制复权与策略分析窗口，默认 365、允许 90–7300；原始日线窗口至少十年，较大的分析窗口会同时扩大原始日线范围。十年前的边界若为休市日，会额外保留之前一根日线用于确认覆盖。腾讯单次最多 640 条，程序向前分页并校验相邻页的重叠日线；复权分析窗口每轮完整刷新，不跨轮拼接不同复权基准。早年前复权价格可能因累计分红变为负数，现有指标要求正价格，因此十年留存采用真实不复权价格，分析仍使用配置窗口。不复权数据仅在已有完整历史且增量与旧数据重叠时增量更新，旧版短窗口和长时间断档会自动全量回补。SQLite 可保存、重读完整窗口，不再截断到 640 条，已有更早日线不主动删除。

每只股票必须通过完整历史校验才计入覆盖率，推荐按 `sync.min_coverage_pct` 判断（默认 95%）。单票可隔离错误会记录原因，整池下载结束后仍保存其他已校验股票的完整窗口；覆盖率不足时不会发布推荐。临时网络、超时、取消或事务错误导致整池下载未完成时保留此前快照；不保存分页未完成的单只股票历史。配置交易日历覆盖范围内仍逐日检查缺口；更早区间依据供应商日线和分页边界校验，不把周一至周五虚构成历史交易日，也不补造停牌日线。首次十年回补会增加下载时间与数据量；升级后执行一次 `stock-watcher sync -config config.yaml` 回补，再重启常驻服务。

持久投递账本使用 `schema_version: 2`、UTF-8 JSON、ISO 日期和带时区 RFC3339Nano 时间；旧版 `schema_version: 1` 的单条待发送记录会在读取时迁移，超过投递窗口 30 天的终态事件会清理。SQLite 中的价格按百万分之一元的定点整数存储，同时保留供应商原始成交量、换算后的股数、来源、复权方式、请求截止日和实际最后一根日线日期；缺字段、非有限数、版本错误和损坏状态都会报错，不自动清空状态。投递账本继续使用 JSON，以便独立保存发送状态。

单个进程持有共享文件锁。JSON 文件先写临时文件、fsync，再原子重命名；共享目录内的软链接被拒绝。`require_cifs: false` 仅适合本地测试，生产应保持 `true`。共享盘故障时停止本轮写入；已保存的数据和待发送记录保留。日志和程序本身占用少量服务器磁盘，行情不会保存第二份服务器副本。

## 飞书配置

在群里添加自定义机器人，用受限权限配置文件或 `/etc/stock-watcher.env` 保存凭证，不要提交到 Git：

```text
FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/...
FEISHU_SECRET=...
```

新配置在 `notify.channels` 中声明通道，并通过 `webhook_env`、`secret_env` 引用环境变量。旧 `feishu.enabled` 配置仍兼容。开启签名时，按[飞书官方签名规则](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)计算 HMAC-SHA256 和 Base64。只有 HTTP 200 且业务码为 0 才确认送达。429、5xx、限流和网络错误持久重试；401/403、签名或关键词错误阻塞对应通道，需要修正配置并运行 `retry feishu-main`。日志不输出 webhook、secret 或原始响应。

已有私有 `feishu.config`（内容为 `webhook: ...`，可选 `secret: ...`）时，在对应 `notify.channels[]` 或旧 `feishu` 节点配置 `credentials_file: feishu.config`。路径相对 `config.yaml` 解析，文件由 Go 读取，不作为 Shell 执行；设置权限为 `600`，不要提交。环境变量优先于文件，文件优先于旧配置内联值；显式空环境变量也会覆盖文件。该文件不会自动启用通知，仍需 `enabled: true`。容器使用此方式时须额外只读挂载文件到配置指定的路径。

推送是至少一次投递：请求成功后、写入确认前异常退出可能重复；重启时在途记录会按可能重复处理。卡片包含固定事件 ID。过了目标交易日 09:30 的消息不再发送。`sync` 和报告预览不依赖通道配置；先以 report-only 模式生成报告，之后启用通道可补发同一数据日的未过期报告。

## 交易日历与数据源

2026 日历来自[深交所休市通知](https://www.szse.cn/disclosure/notice/general/t20251222_618087.html)。T+1 跳过周末和配置中的节假日；日历覆盖到期会报错，应提前按新年度通知更新。未收盘日期不会用于筛选。

日线直接请求腾讯行情 HTTP 接口，沿用旧项目的数据协议。第三方免费行情接口可能限流或改变协议；HTTP 超时默认 10 秒，每只股票请求之间至少 350 毫秒，错误可见且不会生成假数据。运行配置仅包含股池、日线、筛选、飞书和交易日历，修改后需重启生效；不兼容的配置字段会被明确拒绝。
