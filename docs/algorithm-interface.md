# 日常算法接入契约

日常同步与算法的唯一调用边界是 `selection.Engine`：`Descriptor()` 描述版本、周期、复权口径及缺失处理，`Analyze(ctx, Input)` 只计算并返回统一 `selection.Report`。框架负责采集、覆盖率、保存、任务期限和通知。现有 `leader_daily_v1`、`short_horizon_v1` 适配原算法，未修改评分或收益计算。

新增 Go 实现时，在 `selection.DefaultEngine` 注册对应版本，并在 `config.Analysis.Validate` 中增加版本选择。生产配置 `analysis.engine` 明确选择版本；`auto` 兼容现有 `strategy.enabled`。CLI、数据源、存储和飞书无需了解新增计算代码。`Monitor.Engine` 可注入实现进行隔离测试；`engine_test.go` 演示最小虚拟算法。

首版契约接受已收盘日线，声明 `Periods: ["day"]`、`FinalOnly: true`、`MissingPolicy: "exclude"`，复权口径必须匹配输入。短周期内置引擎声明 `Periods: ["day", "30", "5"]`，接收同一 `FetchedAt` 的已完成、不复权 30 分钟与 5 分钟输入。存储层一次读取原生 5m 并派生 30m，引擎验证来源、复权、基础周期、`FetchedAt` 和聚合值一致；15m 只用于诊断，不进入生产契约。`structure_guard.mode` 默认 `shadow`：报告记录日线结构、30m/5m 否决证据和 `eligible_rank`，但不产生可执行推荐，只输出观察排名和结构通过排名；旧 5/15/30 只作诊断，不影响正式结论。切换 `enforce` 后，只有结构通过池内的 `eligible_rank` 能产生正式推荐。结构通过只表示“未被过滤”，不是第一、二、三类买点。尚无分钟记录时结构门控落 `unknown`，不会静默绕过；未知结构只进入观察排名。框架排除未完成及晚于报告日期的分钟线，并将实际使用的多周期窗口与日线一并冻结，重放不会读取当前分钟表。需要模拟成交时声明 `RawRequired`，逐股验证不复权数据配对。其他周期和未知缺失策略会明确拒绝，不能静默忽略算法需求。新报告为 schema 3；schema 1/2 旧报告继续只读，不迁移、不回写。独立分钟实验仍走 experiment 快照路径，实验结果不会自动进入日常推送。

结构门控的数据门槛按本地 365 自然日分析窗口设为：日线 240 根、30m 96 根、5m 240 根。日线不足、分钟不足、错日、错源、复权不一致或 30m 与 5m 不同快照时，`guard_status=unknown`；不会把未知当通过。

实验性 `rebound_signal`（`strategy.EvaluateReboundSignal`）只实现 `watch/armed/confirmed/failed/expired` 状态机，使用日线 qfq 区间、同一冻结快照中的不复权 30m/5m 完成 K 线，并按信号日 qfq/raw 收盘比显式换算价格尺度。它不接管正式推荐，也不得表述为第一、二、三类买点；当前尚未接入 experiment 的逐笔报告与回放，只是策略包内的实验原语，接入前必须补齐快照冻结、逐笔证据和独立样本设计。

输入含按分析窗口裁剪的行情、股池、交易日历和计算配置；框架复制输入，剥离路径、通知凭证和网络客户端。引擎必须主动检查 context，遵守超时／取消；必须返回相同 as_of、目标交易日、版本／复权口径，结果代码只能来自有效输入，不能重复。未知字段、额外周期或不兼容输出需升级契约，不能绕过校验。

## 第一层高召回初筛

`first_stage` 是日报内的独立候选池，不是正式推荐。它只使用信号日及以前的前复权日线，以“未来 3 个交易日最高价相对信号日收盘触及 +1%”为历史标签，将现有机会分与 8 个横截面 z 特征的 `logistic_z` 模型分分别转为日内排名百分位，再等权融合。模型参数以版本化 JSON 编译进二进制，启动时校验 schema、特征顺序、数值范围和 SHA-256；生产进程不调用 Python、子进程或外部推理服务。

默认预算 95 只，飞书只展示综合分前 30 名并合并为一张卡片，第二层消费全部候选。2026-08-27 至 2026-10-15 的 30 个 point-in-time 信号窗口、104 只历史股池评估中，95 只候选的全候选平均召回为 94.06%（开发 20 窗口 93.98%，留出 10 窗口 94.20%），最差单窗口为 91.36%；Top 30 平均精确率为 80.11%，平均覆盖全池达标股票 32.94%。同一窗口改用只使用当日以前已完成 3 日标签的 walk-forward 重训口径，95 只候选平均召回为 93.86%，最差单窗口为 89.19%。90 只候选的平均召回只有 90.30%，余量不足，因此没有继续压缩。评估按交易日截断特征，不使用未来 K 线，并按各版本 `leaders.yaml` 还原历史股池。104 只历史股池下 95 只候选的压缩率为 8.65%；2026-10-20 的 165 只股池实测 148 只可计算，95 只候选的压缩率为 35.81%。这些是历史回测统计，不是未来收益承诺。第一层不改变 `Selected`、`Ranking`、结构门控或风险门槛；初筛异常写入 `first_stage.status=failed`，主报告仍继续生成。`first_stage.push_enabled=true` 时，Top 30 卡片投递到 `first_stage` 路由通道；日报主卡和详情卡投递到 `selection` 路由通道，两类机器人按各自账本重试，互不阻塞。

信号日后第 3 个交易日日报生成后，`first_stage` 机器人会收到窗口回看卡。主口径与模型标签一致：统计信号日后 3 个交易日内最高价相对信号日收盘价的涨幅，达到 `+1%` 即命中。评价同时给出三个指标：全候选召回率为 `全部候选命中数 / 全池窗口达标数`；Top 30 覆盖率为 `Top 30 命中数 / 全池窗口达标数`；Top 30 精确率为 `Top 30 命中数 / 已评估 Top 30 数量`。飞书仍只展示 Top 30，第二层精排使用全部候选。期末收盘涨幅只作参考，不参与命中判断。回看卡只使用已保存的前复权日线，按 `信号日 + 窗口结束日` 生成稳定事件 ID，同一组日期不会重复入队；行情尚未完整时不推送，后续轮询会重试。回看股池从初筛报告的候选与排除项还原，不使用回看时的最新 `leaders.yaml`。

每份新报告保存 `input_id`、`revision`、算法描述、计算配置摘要与具体参数、构建版本。`replay -revision` 以同一构建恢复已冻结输入，独立于之后的复权修订、换源与同日重跑；它只计算，不保存或发送。若构建不同或旧报告缺少来源证据，明确拒绝精确重放，运维须取回记录的制品。配置变更或切换版本后重启；每个制品及数据版本都需保留可恢复备份。

## 第二层 Top10 精排

`second_stage` 只消费第一层已冻结的候选池，按“未来 3 个交易日最高价相对信号日收盘的最大涨幅”连续标签排序，默认输出 Top10。该标签用于排序研究，不是可成交收益；第二层也不改变 `selected`、正式推荐、结构门控、风险门槛或交易建议。

当 `second_stage.push_enabled=true` 时，精排完成后会基于同一份冻结报告生成公众号纯文本稿。稿件包含公众号标题、正文、Top N 名单、逐只技术特征解读、行业分布、数据口径、降级状态和风险提示，并投递到独立的 `second_stage` 飞书路由。文章是结构化报告的确定性转写，不调用 LLM，不重新计算排名；精排名单仍不等于可执行推荐。

生产推理只运行编译进二进制的 Go 树模型。离线阶段用本地 JEV-CPU 对第一层候选按相邻 15 只分组做 listwise 打分，并把 JEV 作为树模型的特征；生产进程不导入 Python、不启动子进程、不调用外部推理服务。JEV 只覆盖第一层全池，不能只看第一层 Top15，否则会丢失理想 Top10 中的大部分候选。

JEV 的 softmax 分数只在同一组内可比，因此树模型同时接收原始分数、组内百分位、组内相对强度和组内最大值，并与第一层排名、机会分、模型分及已冻结技术特征一起训练。最终排序完全由树模型输出，不做 JEV 与树模型的后置加权平均。树模型 JSON 在加载时校验 schema、特征顺序、树结构、数值范围和 SHA-256。

第二层训练样本从历史第一层结果重建 `model_rank` 时使用 `clamp(2 × blend_score - base_rank, 0, 1)`，该等式只在第一层融合权重为 0.5/0.5 时成立。修改第一层模型、融合权重或特征口径后，必须重新生成第一层历史样本并重新训练第二层；不能继续使用旧树模型。

JEV artifact 放在 `<data_dir>/state/jev/<as_of>.json`，schema 为 `schema_version: 1`，必须精确匹配信号日并且包含每只候选的 `adjacent15` 与 `full15_top12` 分数。artifact 缺失、过期、覆盖不全或路径为空时，第二层使用中性 JEV 特征继续输出 Top10，并标记 `degraded=true` 与 `jev_missing`；不会阻断主报告。artifact 存在但 JSON/schema/日期/数值非法时标记 `jev_status=invalid`，同样降级而不是静默通过。

### Laya 离线打分

`scripts/secondstage/laya_scores.py` 提供与 JEV 相同的离线 listwise 协议：按候选分组、对三种选项排列取平均，并输出相同 schema 的 `adjacent15` / `full15_top12` artifact。它支持两个 checkpoint：`official` 对应 `convaiinnovations/laya`（ModernBERT-large，英文官方版），`multilingual` 对应 `convaiinnovations/laya-multilingual`（mmBERT 多语言版）。两者使用完全相同的 prompt、分组和评分代码，便于在同一历史样本上比较。

脚本默认按相邻 15 只分组；研究评估可在三个模型上统一使用 `--group-size 5`，以控制上下文长度和 CPU 开销，此时 artifact 的 `model.group_size` 与 `prompt_version` 会记录实际口径，但字段名仍保持 `adjacent15` / `full15_top12` 以兼容 Go 读取契约。Laya 概率未经校准，跨组不可直接比较；消费方必须先做组内百分位或等价归一化，不能把概率解释为成功概率、收益承诺或投资建议。

Go 生产进程仍只读取离线 artifact，不导入 Laya、不启动 Python 子进程；将 Laya artifact 写到 JEV 读取路径即可作为同 schema 的替换输入。树模型本身仍按 JEV 特征训练，替换为 Laya 后是分布迁移，不应在未重新训练/验证前宣称等价收益。

离线验收以交易日等权的“Top10 平均未来三日最大高点涨幅”为主指标，`NDCG@10` 为辅助指标；同时记录 Top10 第三日收盘收益和 `+1%` 命中率作为风险护栏，并按交易日做 block bootstrap。历史结果只描述样本内/样本外排序表现，不是成功概率、收益承诺或投资建议。

### 当前模型与留出验证

- 模型 `second_stage_gbdt_v1`：80 棵深度 2 的回归树，27 个冻结特征，`max_features=0.4`，SHA-256 为 `21cb6c2a19706381cdb0ce2598ceda743b81227b22391cb5f92ba429d9d4e960`。
- 训练区间 2026-09-03 至 2026-09-21，共 1885 行；只使用标签在 2026-09-28 验证起点前成熟的样本，避免训练标签跨入留出区间。
- 留出区间 2026-09-28 至 2026-10-14，共 8 个交易日、1160 行。Top10 平均未来三日最大高点涨幅为 4.29%，第一阶段融合基线为 3.87%；NDCG@10 为 0.360 对 0.328，`+1%` 命中率为 71.2% 对 68.8%，Top10 第三日收盘收益为 -6.12% 对 -6.48%。
- 按交易日 block bootstrap 2000 次，主指标差值 `+0.420` 个百分点，95% CI `[+0.113, +0.729]`；NDCG、命中率和收盘收益的置信区间跨 0，不能表述为稳定增益。
- JEV 原始分数不能跨相邻组直接比较；留出区间内按原始分数单独排序仅为 1.98%，因此树模型同时使用组内百分位、组内相对强度和 top12 组内占比，而不是把 JEV 当作跨组概率。
- 留出区间只有 8 个交易日且处于下跌市，以上结果只描述该样本的排序表现，不外推为未来收益、成功概率或交易建议。

算法历史研究结果属于计算输出，框架修复不会把“证据不足”“验证失败”直接改成推荐通过。停牌未知缺口继续拒绝，真实停牌元数据接入需另行验证权威来源，不能靠放松完整性条件解决。
