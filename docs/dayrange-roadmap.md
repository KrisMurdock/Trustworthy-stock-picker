# 全天高低价预测后续开发计划

本文承接[日内高低价预测评估指标](dayrange-evaluation.md)。截至 2026-10-21，阶段一至阶段五已经实现：`internal/dayrange` 提供数据审计、盘前确定性树模型、区间校准、预测与核对，独立 `dayrange.db` 保存模型、快照、预测、实际值和评估，CLI、只读 API、`/day-range` 页面、`run` 调度及 `predictor_dayrange` 飞书投递均已接入。阶段六的盘中剩余时段模型尚未实现，接口和页面会明确返回 `phase_six_not_implemented`，不会用盘前结果冒充盘中更新。

实现完成不等于模型已通过生产验证。候选模型必须先通过独立验证门禁才能标记为 `validated`；否则保留历史波幅基线作为正式结果，候选只进入研究档案。评估指标通过也不代表模型可以直接用于推荐或交易。

## 目标与边界

目标是为股票生成两类结果：

1. **盘前全天预测**：在目标交易日 09:00 前，预测当日最终最高价和最低价的点估计、分位数和预测区间。
2. **盘中剩余时段预测**：每个已完成的 5 分钟边界更新当前时点至收盘的最高价和最低价；同时把已出现极值与剩余时段预测合成为全天估计。

第一版先实现盘前模型和收盘核对。盘中模型、精确出现时刻、交易下单、自动止盈止损、收益承诺和实时盘口级策略均不在第一版范围内。

价格统一采用不复权口径。预测标签是目标交易日真实成交区间的最高价和最低价，不把收盘价当作最高/最低价代理，也不把全天高低价拆成递推的若干个 5 分钟预测。

## 开发阶段与任务

### 阶段一：数据审计与标签冻结（已实现）

**交付：** `dayrange` 输入快照、标签审计报告、数据覆盖统计和不可用原因字典。

- 统计股池、历史候选池、指数和行业上下文的可用交易日交集。
- 固定盘前截止时间、参考价格、除权处理、停牌、涨跌停和缺失分钟线规则。
- 生成 `high`、`low` 标签前检查当日完整收盘、来源一致和交易日状态；未核对样本只能进入 unresolved 计数。
- 记录历史预测时点可见的数据边界，禁止使用目标日收盘、目标日最高/最低或事后行业归属。
- 建立历史波幅、ATR、上一日区间和固定参考池分位数基线。

**退出条件：** 随机抽取的样本可以逐条说明参考价、输入截止、标签来源、缺失状态和除权口径；修改目标日后续行情不能改变盘前快照。

### 阶段二：盘前分位数模型（已实现，生产有效性待独立验证）

**交付：** `internal/dayrange/model.go`、特征构建、模型 artifact、训练和滚动评估入口。

- 直接预测 `log(high/reference_price)` 和 `log(low/reference_price)`，分别输出低、中、高分位数。
- 首版保留纯 Go、确定性树模型；不递推调用现有5分钟模型。
- 特征分三层：个股日线、市场环境、行业/参考池相对强弱。每层都能独立关闭，缺失时显式为 unknown。
- 点估计、分位数和区间分别记录 feature version、训练区间、校准区间、代码版本和 checksum。
- 训练、校准、验证按时间顺序分离；模型不能依据验证结果反复调参。

**退出条件：** 模型优于历史波幅基线的结论至少在一个完整独立测试窗口成立，并且没有明显更宽的区间换取覆盖率；否则保留基线作为正式结果，模型只进入研究档案。当前代码已实现该门禁，但是否通过仍取决于具体数据和 `dayrange.db` 中的评估记录，不能据源码存在推断模型有效。

### 阶段三：区间校准与可靠性审计（已实现）

**交付：** 分位数校准、滚动 conformal 残差、可靠性分组报告。

- 最高价和最低价分别校准；另行计算联合覆盖率，不用两个边际覆盖率的平均值替代。
- 以交易日为 bootstrap 单位；按月份、市场状态、波动水平、股票和预测时点分组。
- 同时报告覆盖率、区间宽度、区间评分、上下界突破比例和突破距离。
- 设定最低有效交易日、最低股票数和最低已核对样本；不足时返回 `insufficient_data`。
- 校准窗口发生市场结构变化时，保留旧校准版本并允许回退到基线。

**退出条件：** 主测试窗口、上行/下行/震荡状态均有覆盖率和区间宽度记录；不允许只展示总体平均覆盖率。

### 阶段四：盘前生产链路与审计存储（已实现）

**交付：** 独立 `dayrange.db`、模型生命周期、盘前预测档案、收盘后核对任务，以及只发往 `predictor_dayrange` 的分页飞书投递账本。

当前 `dayrange.db` schema 1 包含以下版本化记录：

- `dayrange_snapshot`：按类型冻结的训练数据集与盘前输入快照；模型 artifact 保存在模型运行记录中。
- `dayrange_model_run`：模型ID、特征版本、训练/校准区间、适用日期、指标摘要、checksum。
- `dayrange_prediction`：代码、目标日期、模式、预测时点、参考价、点估计、分位数、区间、输入快照ID。
- `dayrange_actual`：实际高低价、数据来源、核对时间、核对状态和错误原因。
- `dayrange_evaluation`：不可变评估报告及指标版本。
- `dayrange_audit`：数据覆盖、标签来源、特征可用性和不可用原因审计。

写入继续遵守 CIFS 检查、单写进程锁、SQLite `DELETE/FULL` 配置和原子状态写入。模型缺失、过期、数据过期、校准不足或共享盘不可用时不发布旧预测，不回退服务器本地目录。

`state/dayrange-delivery.json` 使用共享 `notify.Ledger` schema 2。事件 ID 固定为 `dayrange:premarket:<目标日>:<页码>`，分页按依赖顺序发送；同一目标日、同一页在重启、重复训练或重复预测后不会再次入队，临时网络错误退避重试，09:30 后未发送事件过期。`STOCK_WATCHER_DAYRANGE_PUSH_ENABLED=false` 时仍保存预测，但不创建投递事件。

**退出条件：** 重启、重复执行、训练取消、写入失败、实际值缺失、数据库升级和模型 checksum 错误都有明确状态；预测和实际档案可按模型ID重放。

### 阶段五：CLI、只读 API 与网页（已实现）

**交付：**

```text
train-dayrange
predict-dayrange
reconcile-dayrange
status-dayrange
replay-dayrange
GET /api/day-range?date=YYYY-MM-DD[&code=...]
GET /api/day-range/status
GET /api/day-range/evaluation?...
```

- CLI 的训练、预测、核对和重放均支持显式日期；离线评估不写生产库。
- `predict-dayrange` 保存预测后按相同命名通道路由和账本推送；离线训练不发送消息。
- `/api/day-range` 只返回已保存结果，不在请求中训练或补行情。
- 页面同时展示盘前原始预测、实际高低价和区间覆盖状态；最新盘中预测位置明确标注为阶段六尚未实现。
- 缺失、过期、模型不可用、实际值未核对、覆盖率不足都显示状态文字和可追溯原因。
- 不新增账号或角色；沿用现有只读网页和受控写入边界。

**退出条件：** 用真实浏览器验证 DOM、URL、标题、控制台、网络请求、空结果、超时、错误恢复和数据日期；容器形态使用生产启动命令和路径前缀复验。

### 阶段六：盘中剩余时段模型（未实现）

**交付：** 盘中输入冻结、剩余时段标签、5分钟更新、全天合成和分时评估。

- 模型目标只覆盖当前已结束K线之后到收盘的高低价。
- 全天最高价为 `max(已出现最高价, 剩余时段最高价)`；全天最低价为 `min(已出现最低价, 剩余时段最低价)`。
- 评估固定在 09:35、10:30、11:30、14:00、14:30 等截点，和“极值不再刷新”基线比较。
- 指数分钟线、稳定参考池广度、当前已实现波动和市场状态必须有统一时间戳；数据迟到时标记 unknown。
- 盘中模型不得使用同一时点后才到达的指数、股票或成交数据。

**退出条件：** 剩余时段区间在多个截点优于不更新基线；接近收盘的高覆盖率不能单独作为模型有效证据。

## 预测与评估契约

每条预测至少保存：

```text
model_id
feature_version
target_date
mode: premarket | remaining | full_day
as_of
input_through
code
reference_price
point_high / point_low
quantiles_high / quantiles_low
interval_high / interval_low
input_snapshot_id
created_at
```

每条实际结果至少保存：

```text
actual_high / actual_low
source
observed_through
resolved_at
status: resolved | unresolved | invalid
reason
```

评估必须调用 `internal/dayrange`，使用[评估指标文档](dayrange-evaluation.md)定义的 `day_equal` 主聚合、`pooled` 辅助聚合、配对日块 bootstrap、边际/联合覆盖和基线配对规则。新模型不能自定义一套只在页面显示的指标。

## 验证门禁

每个阶段必须覆盖以下断言：

- **成功路径**：完整交易日、完整高低价、有效模型和有效校准能生成可重放结果。
- **未登录/权限边界**：预测接口保持现有只读行为；任何写入口继续受现有 loopback/动作头规则保护。
- **异常与超时**：上游数据缺失、模型读取超时、数据库忙、训练取消、浏览器请求超时均有明确状态，不发布旧结果冒充新结果。
- **配置缺失**：模型、校准文件、参考价、交易日历、上下文数据或必要环境变量缺失时拒绝正式预测或降级到已验证基线。
- **用户可见状态**：区间、覆盖率、样本数、预测时点、数据截至时间、实际核对状态和模型版本均可见。
- **生产形态**：本地验证使用同一 Go 二进制、容器启动命令、路径、环境变量、端口和反向代理约束；部署后再用真实 URL 重跑关键验收。

发布前必须记录提交 SHA、模型 checksum、镜像 digest和评估报告摘要。无法访问真实部署、账号或必要外部依赖时，交付只能写“本地验证通过，部署后未验证”。

## 暂不进入开发的研究项

以下事项必须等盘前模型和盘中剩余时段模型完成独立验证后再评估：

- 预测最高/最低价出现的精确时刻；
- 盘口订单流、逐笔委托和市场深度；
- 新闻、公告和临时停牌事件的实时文本特征；
- 将高低价预测直接转化为自动买卖、止盈止损或仓位建议；
- 用深度 Transformer 或跨股票图模型替换当前纯 Go 树模型；
- 把预测结果写入正式选股分、推荐门槛，或并入选股日报的飞书主卡；独立的 `predictor_dayrange` 研究卡片不属于此限制。

这些方向都需要新的输入时点、数据保留策略和独立样本外证明，不能作为盘前模型的隐式扩展。
