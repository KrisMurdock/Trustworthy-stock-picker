# 单股价格策略计算器

`scripts/calculate_strategy.sh` 将账户资金、单股投入上限、亏损预算和止盈目标转换为底仓及加仓数量上限。它离线计算，不读取真实账户、不获取行情、不下单、不修改内置参数或持仓文件。

适用范围是现金买股、一次底仓、可选的一次加仓、最后全部卖出。可以输入多批历史买入。融资、部分卖出、做 T 后的成本归集，以及多只股票之间的组合风险需要另外建模。

## 运行方式

### 网页计算器

启动 `stock-watcher run`（或 `make run`）后，在股池看板导航中点击「仓位计算」，默认地址为 `http://127.0.0.1:8080/calculator`。也可通过相同路径直接访问；端口沿用内置 `web.listen` / `STOCK_WATCHER_WEB_ADDR`，反向代理需保留 `/calculator` 和 `/assets/` 路径。容器仍使用同一个 Go entrypoint 和 8080 端口。

1. 填写账户总资产、可用现金、单股投入上限、整笔最大亏损金额、账户风险比例和策略止损价。
2. 选择「首次建仓」或「已有持仓」。已有持仓可添加最多 100 批历史买入，分别填写价格、股数和已付买入费用。
3. 可选填写加仓价。设置净止盈收益率（默认 3%）或固定净利润金额，并填写费用和滑点。交易规则默认 200 股起、步长 1；可展开调整。
4. 点击「计算仓位」，查看每批最多可买股数、资金比例、总风险占用、净止盈价和资金止损边界。数量不足最小买入要求时显示 0 股及原因。

「载入 215 股示例」只填入演算参数，账户资金、止损位、费用均是假设；请核对后计算。参数修改后旧结果立即隐藏，重新计算才显示新结果。「清空重填」恢复初始状态。

网页使用浏览器内的精确 BigInt 分数运算决定买入数量和价格取整，不把账户金额发送到服务器、不写入 localStorage、sessionStorage、Cookie 或 URL。参数仅存于当前页面内存；刷新后清空。从浏览器返回缓存恢复页面时也会清空。行情接口失败或空数据库不影响计算，计算模块加载后可离线使用。首次访问仍需能够加载网页资源；模块加载失败、网关拒绝或超过 10 秒未加载时显示重载入口。

浏览器模型与脚本采用相同公式、默认值和输入校验。非终止小数的比例及均价在模型输出时截取 40 位小数，界面只显示所需位数；买入股数和按报价单位取整的退出价格使用精确分数。网页展示价格至少保留报价单位的小数位，避免把细粒度目标价显示成低于真实门槛的价格。它没有新增后端计算接口；Go 仅提供嵌入的静态资源，生产运行不依赖 Node 或 Python。

### 命令行脚本

依赖 Bash 和 Python 3.8 及以上版本，只使用 Python 标准库。金额使用 `Decimal` 十进制计算。这个工具在宿主机运行，不包含在生产 Go CLI 镜像或发布包中。

```bash
# 在终端逐项输入；无参数且 stdin 是终端时也会进入交互模式
./scripts/calculate_strategy.sh --interactive

# 参数、默认值与帮助
./scripts/calculate_strategy.sh --help
```

非交互环境必须明确提供参数，避免等待输入。`--interactive` 可读取重定向的答案；提示写入 stderr，因此可与 `--json` 一起使用。

### 测算已有 215 股还能否加仓

下面的账户资金、45 元止损、费用和滑点均为演算假设，不代表长鑫科技的实际支撑位或券商报价。现金为当前剩余现金，不能再减一次历史买入金额。

```bash
./scripts/calculate_strategy.sh \
  --account 100000 --cash 80000 --budget 20000 \
  --max-loss 500 --risk-pct 0.5 \
  --stop 45 --slippage 0.10 \
  --hold 47.05:215:10 --add-price 46 \
  --buy-fee 0 --sell-fee 20 --target-pct 3
```

预期结果：现有风险占用 492.25 元，剩余风险 7.75 元；不含新增买入费用时也只允许新增 7 股，低于默认最小买入数量 200 股，因此加仓输出 **0 股**。总买入支出为 10,125.75 元，净赚 3% 的目标成交价向上取整为 **48.61 元**。`--buy-fee 0` 会显示费用缺失提示，实际下单测算应填写费用。

`--hold` 的格式是 `买入价:股数[:已付买入费用]`，可以重复传入：

```bash
./scripts/calculate_strategy.sh \
  --account 100000 --cash 80000 --budget 20000 \
  --max-loss 500 --stop 45 --slippage 0.10 \
  --hold 47:100:5 --hold 46:100:5 \
  --sell-fee 20 --target-profit 500 --json
```

也可用历史加权平均买入价和总股数作为一批持仓，但此时无法区分各批的盈利与亏损，风险占用可能低于逐批输入时的保守估计。历史持仓数量不受“本次最少买入股数”限制。

### 规划底仓和后续加仓

```bash
./scripts/calculate_strategy.sh \
  --account 100000 --cash 80000 --budget 20000 \
  --max-loss 1000 --risk-pct 1 \
  --entry 47.05 --initial-risk-pct 50 --add-price 46 \
  --stop 45 --slippage 0.10 \
  --buy-fee 10 --sell-fee 20 --target-pct 3
```

此例底仓允许 223 股，假设底仓成交后，加仓允许 206 股；累计成交金额 19,968.15 元，买入费用合计 20 元，风险占用 746.05 元。1% 是为展示两批计算而设的参数，不能据此扩大自己的风险预算。

`--entry` 与已有持仓 `--hold` 互斥；已有持仓时使用 `--add-price`。未提供加仓价时只分析底仓或现有持仓。底仓无法建立时，不会跳过底仓限制直接买入下一批。

## 参数及单位

所有金额单位为元。百分比按百分数输入：`0.5` 表示 0.5%，`3` 表示 3%。仅接受非负十进制普通表示，数值不超过 10^12，最多 8 位小数；拒绝负数、NaN、Infinity 和科学计数法。

| 参数 | 含义 | 默认值或要求 |
| --- | --- | --- |
| `--account` | 账户总资产 A，现金＋持仓当前市值 | 必填，正数 |
| `--cash` | 当前可用现金 C，已扣历史买入支出 | 必填，非负且不超过 A |
| `--budget` | 单股累计买入成交金额上限 B，不含费用 | 必填，正数且不超过 A |
| `--max-loss` | 整笔交易心理亏损上限 L，包含费用 | 必填，正数 |
| `--risk-pct` | 账户风险比例 r | 0.5%，范围 (0,100] |
| `--stop` | 根据策略失效条件设定的止损触发价 S | 必填，正数 |
| `--slippage` | 每股不利成交价差 g | 0，零值会提示 |
| `--entry` | 首次买入价 P0 | 无历史持仓时必填 |
| `--hold` | 已有买入批次，含该批已付费用 | 可重复；省略费用按 0 处理 |
| `--initial-risk-pct` | 底仓使用的可分配风险比例 α | 50%，范围 (0,100] |
| `--add-price` | 计划下一次加仓价 Pa | 可选 |
| `--buy-fee` | 每次新增买入费用估算 Fb | 0，零值会提示 |
| `--sell-fee` | 最终全部卖出总费用估算 Fs，含税 | 0，零值会提示 |
| `--target-pct` | 净利润占实际买入支出的比例 t | 3% |
| `--target-profit` | 固定净利润金额 G | 与 `--target-pct` 互斥，正数 |
| `--min-shares` | 新订单最少买入数量 | 200 |
| `--lot-step` | 股数步长 | 1；最小数量须为步长整数倍 |
| `--tick` | 价格最小变动单位 | 0.01 |
| `--json` | 结构化输出 | 默认可读文本 |

费用采用用户填写的固定金额估算，不自动读取券商佣金、最低佣金或税率。历史费用填在 `--hold` 中，`--buy-fee` 只计入新生成的非零订单。底仓和加仓使用同一个新增订单费用估算；如果两批费用不同，可以按较大值预留，或成交后用实际持仓重新测算。

默认数量规则对应科创板常见买入申报要求。主板通常使用 `--min-shares 100 --lot-step 100`。脚本不识别股票代码和板块，用户必须核对实际市场规则。计划买入价和止损价必须符合报价单位；历史均价可以不是整分。

## 计算模型

### 1. 整笔风险预算

```text
R = min(L, A × r)
假设止损成交价 Se = S - g
```

R 是底仓和全部加仓共用的预算。脚本不会在每次加仓时重置它。假定 g 小于 S，所有新增买入价高于 S。

### 2. 底仓数量

先预留计划内费用。只有底仓时 `F计划 = Fb + Fs`；同时规划加仓时 `F计划 = 2 × Fb + Fs`。

```text
底仓价格风险额度 = α × max(0, R - F计划)
风险数量上限 = floor(底仓价格风险额度 / (P0 - Se))
投入数量上限 = floor(B / P0)
现金数量上限 = floor(max(0, C - Fb) / P0)
底仓数量 = 合法向下取整(min(风险数量上限, 投入数量上限, 现金数量上限))
```

合法向下取整：先向下取股数步长的整数倍，再判断是否达到最小买入数量；不足时返回 0。α 分配的是风险，最终资金仓位由成交金额计算，不等于 α。

### 3. 加仓数量

历史成交金额为 I，历史买入费用合计为 F已付，各批数量和价格为 Qi、Pi：

```text
I = Σ(Qi × Pi)
已有价格风险 = Σ(Qi × max(0, Pi - Se))
可用于新增价格风险 = max(0, R - F已付 - Fb - Fs - 已有价格风险)

风险数量上限 = floor(可用于新增价格风险 / (Pa - Se))
投入数量上限 = floor(max(0, B - I) / Pa)
现金数量上限 = floor(max(0, C - Fb) / Pa)
加仓数量 = 合法向下取整(min(三个数量上限))
```

盈利批次的浮盈不抵消其他批次风险。现有持仓超出风险或投入预算时，程序仍展示持仓信息，但新增数量为 0。加仓计算没有额外乘 α：它最多使用剩余风险。若需要预留第三批，应主动减少本次数量，后续重新输入实际持仓。

整个计算使用同一个策略止损价。不要为容纳加仓而下移止损。脚本无法验证买入信号、加仓信号或止损逻辑的合理性，也不把“可加仓”视为买入建议。

### 4. 仓位和止盈

设最终持仓总数为 Q，累计实际买入支出为 K：

```text
K = I + F已付
成交均价 = I / Q
账户投入比例 = I / A
计划投入使用比例 = I / B

收益率模式：G = K × t
固定金额模式：G = 用户输入的目标利润
目标卖出成交价 T = 向上取合法报价((K + G + Fs) / Q)
该价格的净利润 = Q × T - Fs - K
```

因此净赚 3% 对应 `T = (1.03 × K + Fs) / Q`，再向上取合法报价。收益率的分母是实际买入支出，不是账户总资产或尚未投入的预算。加仓后收益率目标对应的利润金额会增加；固定金额目标则保持不变。

资金止损边界用于检查亏损预算：

```text
资金止损边界成交价 = 向上取合法报价(max(0, (K - R + Fs) / Q))
含滑点的资金止损触发边界 = 向上取合法报价(max(0, (K - R + Fs) / Q + g))
```

它不替代用户输入的策略失效价 S。若预算可覆盖全部成本，边界可能为 0；0 仅表示该假设下没有正的价格边界，不是有效卖单。行情跳空或无法成交时，真实损失仍可超过 R。

## 参数选择与模型限制

固定风险仓位以允许亏损和退出距离反推数量。[CME 仓位教程](https://www.cmegroup.com/education/courses/trade-and-risk-management/proper-position-size)提供了这一基本方法；[CME 的 2% 规则说明](https://www.cmegroup.com/education/courses/trade-and-risk-management/the-2-percent-rule)也指出阈值本身是人为选择。脚本默认 0.5% 风险、50% 首次风险分配只是试验起点，没有最优性保证。

可以用连续亏损作压力测试：如果每次都恰好亏当时账户的 r，连续 m 次后的回撤为 `D = 1 - (1-r)^m`。要求连续 10 次亏损的回撤不超过 5%，可反推 `r <= 1 - 0.95^(1/10) ≈ 0.512%`。该推导假定串行交易、每次重新按账户金额分配风险，没有额外跳空损失；它不能保证真实最大回撤。

止损价可以参考策略结构或 ATR 波动距离。ATR 衡量波动，不预测方向；例如 `S = 买入价 - k × ATR` 中的 k 仍需验证。脚本不下载行情或计算 ATR。[Fidelity ATR 说明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/atr)

凯利方法依赖胜率和收益分布估计，并可能经历较大回撤。策略样本不足时，本工具采用固定风险预算，不提供自动凯利仓位。[带风险约束的凯利研究](https://stanford.edu/~boyd/papers/pdf/kelly.pdf)

固定止盈不代表正收益策略。盈亏平衡胜率为 `平均亏损 / (平均盈利 + 平均亏损)`。以 47.05 元买入、45 元退出、赚 3% 止盈为例，不计费用就需要超过约 59.2% 的胜率。复盘应按完整交易统计净盈亏、最大浮亏、持有时间和连续亏损，而不能把每次补仓算成独立成功交易。

普通 A 股的 T+1、跳空、跌停和流动性不足会影响退出；止损触发价不是保证成交价。[上交所规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)、[SEC 止损订单说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15)。单股预算也不能替代组合风险控制，多只相关股票同时下跌时需要合并评估。

## 输出与退出码

JSON 使用 `schema_version: 1`，UTF-8 编码。金额、价格、百分比均为十进制字符串，股数为整数，状态为字符串，标记为布尔值，无持仓时 `current_position` / `final_position` 为 `null`。

- `inputs`：本次有效输入及默认值，帮助复核假设。
- `risk_budget`：整笔风险预算。
- `orders`：底仓和/或加仓情景；`eligible` 表示数量约束允许，`blocked` 表示无法构成合法买入订单。
- `limits_shares`：风险、投入、现金三个数量上限；`blocked_by` 和 `binding_limits` 解释限制来源。
- `position_after`：该批假设成交后的持仓；未成交的订单不扣费用或现金。
- `final_position`：全部允许订单假设成交后的持仓。`risk_remaining` 可以为负，以保留超预算证据。
- `warnings`：费用、滑点及模型边界提示。

底仓无法建立时，后续订单只含状态、价格、零股数和 `no_initial_position` 原因，不含成交后字段。现金只扣新增订单及其费用，不扣历史成本，也不会提前扣最终卖出费用。

退出码：计算成功为 0（包括无法加仓）；参数错误或交互输入提前结束为 2；用户 Ctrl+C 取消为 130；缺少 Python 为 127。程序不会自动保存账户数据；使用 shell 重定向保存 JSON 时，应自行选择私有位置。
