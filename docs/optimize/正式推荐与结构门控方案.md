# 正式推荐与结构门控方案

本文按 `33ab655` 核对日常推荐的调用边界、统计门槛和分钟结构门控。初筛、精排、预测以及 AI 解释都有独立输出，不能据它们存在就认定某只股票进入正式推荐。

## S｜场景与边界

行情框架先完成数据同步和发布覆盖率检查，再调用 [`selection.Engine`](../../internal/selection/engine.go)。引擎只计算统一报告；持久化、调度和投递分别见 [数据同步](数据同步模块方案.md)、[存储快照与重放](存储快照与重放方案.md)、[通知调度与投递账本](通知调度与投递账本方案.md)。

```text
已校验的日线、独立不复权成交序列、可选分钟输入
  → selection.Execute：冻结输入与校验
  → 日线趋势引擎 / 短周期策略引擎
  → 历史证据、严格损失规则、留出验证
  → 有分钟输入时应用结构门控
  → Report.Ranking / Report.Selected
  → 附加初筛、精排、阶段解释及图表
```

短周期报告的 `Ranking` 是观察结果，`Selected` 才是正式选中列表；schema 1 日线分支不填 `Ranking`；`GuardPassed` 是结构通过数量，不能替代正式推荐数量。机会分不是收益概率。

## T｜输入输出和验收条件

### 引擎契约

`Descriptor()` 返回算法版本、周期、复权、原始价格要求和缺失策略；`Analyze(ctx, Input)` 返回 `Report`。`auto` 在策略关闭时选择 `leader_daily_v1`，开启时选择 `short_horizon_v1`；显式配置与策略开关不兼容会失败。

| 引擎 | 周期/价格 | 主要输出 |
| --- | --- | --- |
| `leader_daily_v1` | 日线、配置复权口径 | schema 1 趋势筛选结果 |
| `short_horizon_v1` | day/30m/5m；qfq 特征、none 成交 | 无分钟 schema 2；有分钟 schema 3 |

执行器深拷贝输入，剥离路径、网络客户端和凭证等不属于计算的数据。股票必须来自股池且不重复，日线口径与描述一致，要求原价的引擎必须有配对 none 历史。分钟必须已完成、日期不晚于 `as_of`，并满足周期、来源、复权、单位、基础周期和抓取批次的一致性及 5m/30m 聚合校验。

返回值再次检查 schema、日期、目标交易日、口径、选股开关、代码范围和唯一性，校验初筛/精排等附属结果，再附加算法描述、配置摘要和构建版本。取消依赖引擎配合，返回后也检查 context；框架不提供强制终止任意计算函数的保证。

### 必须区分的开关和阈值

生产内置配置开启策略及选股；通用 `Defaults()` 与生产 `Builtin()` 不等同。默认短周期目标 3%、止损 -3%、最长持有 5 日、预算 20000 元、入场跳空阈值 3%、证据 60 笔/40 信号日、留出 40 日、最低排名分 60。完整字段见 [`config/strategy.go`](../../internal/config/strategy.go)。

`selection.min_score=70` 属于旧日线趋势分支，不是短周期策略的 60 分门槛。`selection.enabled=false` 可以保留排名与分析，但不生成正式选中列表。

核心验收断言：

1. qfq 只能用于特征与结构，模拟买卖必须用 none 价格并计入费用。
2. 缺少合格规则证据或留出失败的候选不能靠结构通过进入正式推荐。
3. 有分钟输入且 `shadow` 时正式推荐为空；`enforce` 时只从结构通过的候选选择。
4. 无分钟输入实际走原日线分支；配置 `enforce` 本身不会改变这一分流。
5. 初筛、精排、阶段解读和图表不得自动改写正式选中结果。

## A｜算法与分支

### 1. 日线趋势分支

策略关闭时，[`selection.go`](../../internal/selection/selection.go) 计算日线趋势：收盘高于 MA20、MA5 > MA10 > MA20、量比达到默认 1.2、DIF > DEA、RSI 50～80、当日涨跌 -3%～7%，并达到默认 70 分。

排除特殊名称、日期陈旧、当日无成交及不完整数据；按分数降序、代码升序排序，再受 Top N 和选股开关约束。没有任何可分析股票时返回错误，而不是生成成功的空数据报告。该分支不执行下述短周期历史证据和成交模拟。

### 2. 短周期历史证据

[`strategy/research.go`](../../internal/strategy/research.go) 对齐前复权与不复权历史。最新日必须等于 `as_of`，特征至少 60 根，最近原始成交量必须有效；特殊名称和不满足条件的股票排除。每个历史信号只使用当日及之前数据提取特征，相对五日收益以同日可用全池均值为基准。

历史标签覆盖 2.5%/3% 目标和 1/3/5 日等允许周期，独立校验下一交易日和退出窗口。公司行动导致价格口径不可直接比较时保留未完成结果，不用后来的复权序列假装当时可成交。

候选先匹配规则，再从满足历史证据和损失门槛的非基准规则中选择下界最高的证据；并列按规则名稳定排序。某条匹配规则超损只跳过该规则，其他规则仍可提供合格证据；`historical_net_loss_limit_breached` 风险字符串本身不是整股硬否决条件。排名分为：

```text
有合格证据：score = 0.5 × base_score + 50 × evidence.lower_bound
无合格证据：score = 0.5 × base_score
```

`lower_bound` 是 0～1 的历史统计量，不是 0～100，也不是已校准的未来成功率。基础机会分的分项见 [`strategy/features.go`](../../internal/strategy/features.go) 的 `opportunityFormula`；报告中的评分推导用于复算，不能省略证据融合后直接用初始分排名。

日线 `Recommended` 还要求证据存在、分数至少 60、ATR14 不超过 4%、距 MA20 不超过 10%、五日收益不超过 12%。上影风险有评分和提示作用，不能把每条风险提示都解释为独立硬否决。

### 3. 证据与留出门槛

[`gates.go`](../../internal/strategy/gates.go) 和 [`risk.go`](../../internal/strategy/risk.go) 共同控制：

| 项目 | 当前规则 |
| --- | --- |
| 完成样本 | 至少 `max(30, min_evidence)`，默认 60 |
| 信号日期 | 至少 `max(30, min_training_days)`，默认 40 |
| 未完成 | 不得有未决交易或不完整 cohort 信号日 |
| 损失 | 净损失达到 3% 即违规，含比较容差；NaN/Inf 不得放行 |
| 平均收益 | 必须为正；存在收益 bootstrap 时下界也须为正 |
| 相对基准 | 命中率必须高于全池基准 |
| 增量区间 | 存在配对增量 bootstrap 时，下界为正且至少 30 配对日 |

存在 cohort 版本时，日期数、完成数、平均收益、不完整日以及对应 bootstrap 切换到 cohort 统计；命中率比较仍使用交易级 `Targets/Samples`，不能声称所有指标都已按日期等权。日常规则证据的 `statsFor` 本身不附 cohort，滚动/留出汇总另行附加。日期下界的调整也不能被包装为严格概率校准。

信号日期数量严格超过“最少训练日 + 留出日”（默认大于 80）时，按最近 40 个信号日形成冻结留出验证；开发标签跨入边界的样本清除。留出要求方法为 `frozen_holdout`、至少 30 交易与 30 信号日、无不完整日、严格损失状态 `observed_pass`、正平均收益、适用 bootstrap 下界为正并优于全池。cohort 增量比较还要求足够配对日；旧口径保留对应收益比较。

最终验证还要求 `research.Calendar.Complete`；统计条件满足但日历不完整也不能通过。留出失败会清除正式 `Recommended` 并附加 `holdout_validation_not_passed`，但保留观察排名。不能把“仍能看到排名”误判为“留出通过”。

### 4. 成交与损失口径

[`trade.go`](../../internal/strategy/trade.go) 用下一交易日开盘价加单边滑点、向上取分买入，校验跳空、无成交、封板、预算和实际价格范围。佣金最低收费、过户费、卖出印花税和双向滑点进入净收益。最早卖出日是买入后的下一交易日。

止盈不是最高价刚好碰到阈值就证明成交，还要求价格穿透；同根同时触发止盈与止损时按止损优先。止损价预留费用、滑点和分位取整，使模型计划的损失严格小于 3%，但跳空和封板可能导致实际模拟损失更大；这种结果必须触发风险否决，不能宣称止损保证最大亏损。

缺失退出交易日、价格限制不明或无法退出时保留删失/未完成状态，不可按到期收盘补造结果。价格限制按实际退出交易日计算。

### 5. 何时执行结构门控

[`selection.go`](../../internal/selection/selection.go) 先按分钟切片是否为空分流：

| 分支 | 行为 |
| --- | --- |
| `len(minutes)==0` | `strategy.Analyze`，`legacy_daily`，schema 2；不进入结构门控 |
| 有分钟，`shadow` | 记录观察/合格视图，所有正式 `Recommended=false`，Selected 为空 |
| 有分钟，`enforce` | 只允许结构 pass 候选保留符合日线门槛的推荐资格 |

因此，“shadow 保留旧正式推荐”和“enforce 无分钟必然过滤全部股票”都不符合当前代码。空分钟切片与含有不足分钟数据的切片不同：后者进入门控后可得 `unknown`。

[`chan_selection.go`](../../internal/strategy/chan_selection.go) 的 `applyStructureGuard` 保存 `DailyRecommended`、观察分及 `ObservationRank`，再构建逐股结构证据。结构通过后，在通过池内重算相对收益和机会分、生成 `EligibleRank`；未知和失败候选不能挤占合格排名。

当前 `EligibleRecommended` 继承 `DailyRecommended` 并排除留出失败、预算不足等硬门槛，不直接采用重排过程重新算出的 `Recommended`。也就是说，合格池重算影响分数和顺序，不能将其理解为重新放宽或完整重做日线推荐资格。

`enforce` 将合格池置前，按合格分排序，其余观察股票追加在后；最终只从仍有正式资格者取 Top N，没有合格者输出空推荐，不从 unknown/fail 补位。

### 6. 结构证据的精确定义

[`structure_guard.go`](../../internal/strategy/structure_guard.go) 的日线部分使用至少 240 根、最终日期等于 `as_of` 的前复权序列。[`internal/chanlun`](../../internal/chanlun) 计算包含关系、分型、完成笔及笔重叠区；`stroke_zone` 是连续三个完成笔的交集，不等于严格缠论中枢。

- 无完成笔：unknown。
- 有最近笔重叠区：收盘低于其下沿则 fail；至少两个区间且最新区间中点下降、收盘又低于最新中点也 fail；其余可通过日线部分。
- 无重叠区：最后完成笔向上，存在最近底分型，且收盘不低于该底分型最高价时可通过；否则 unknown。

分钟以信号日 qfq/none 收盘比率转换口径，要求 30m/5m 同批次且相互一致：

| 周期 | 最小总根数 | 信号日完整性 | 否决/未知条件 |
| --- | --- | --- | --- |
| 30m | 96 | 当日 8 根，末根 15:00 | 转换后最新收盘低于日线区间下沿则否决；缺完成底分型则 unknown |
| 5m | 240 | 当日 48 根，末根 15:00 | 最新收盘低于 30m 底分型最低价则否决 |

两个分钟周期还各自要求至少存在分型、完成笔或区间，否则返回 `minute_no_structure`；仅根数充足不等于结构可用。重复、错误日期、未完成 bar、来源或复权不一致、快照不同批次和不一致聚合不能当通过。证据包括 `data_status`（ok/insufficient/invalid）、`guard_status`（pass/fail/unknown）和 `signal_status`；结构 pass 时信号状态仍可为 `not_evaluated`，不代表识别出第一、二、三类买点。
