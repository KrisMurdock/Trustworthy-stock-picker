# 股池初筛方案

核对日期：2026-10-29。源码基线：`3e2510b`。本文按当前实现记录输入、特征、排序与复盘契约，供复现或重建使用；源码状态不代表线上部署状态。

## S｜情境：正式推荐之外保留研究候选池

正式推荐受历史样本、收益、风险和结构门槛约束，某天可能没有入选股票。初筛在同一报告中生成独立研究池，供第二层精排和初筛卡片使用，不修改正式推荐的 `Selected`、`Ranking` 或风险门槛。

[生产内置配置](../../internal/config/builtin.go)启用 `first_stage.enabled` 与 `push_enabled`，候选预算沿用 [DefaultFirstStage](../../internal/config/first_stage.go) 的 95 只。95 是上限；可计算股票不足时不补齐。推送展示前 30 名，精排消费全部初筛候选。通用默认配置关闭计算和推送，不能把它与 `config.Builtin()` 混为一谈。

## T｜任务：冻结信号日输入，输出可重算的排序

计算入口是 [firststage.Analyze](../../internal/firststage/analyze.go)：

```go
Analyze(histories []market.History, pool []config.Stock, opts Options) (Report, error)
```

`Options` 包含 `AsOf`、`Target`、`Adjust`、`Budget`、`PushEnabled`、`Now`。初筛不下载行情、不读取数据库、不发送通知。为了逐字节复现时间字段，调用者应固定 `Now`；零值会使用当前时间。

| 契约 | 当前行为 |
| --- | --- |
| 日期与复权 | `AsOf`、`Target` 必须能解析为日期，`Adjust` 必填；函数本身不验证目标日是否是下一交易日 |
| 生产输入 | [配置校验](../../internal/config/config.go)要求启用初筛时 `daily.adjust=qfq`；包级函数只比较传入复权口径是否一致 |
| 预算 | 1～500；实际候选数为 `min(Budget, Eligible)` |
| 成功 | `status=ok`，候选非空，按最终名次排列 |
| 无有效股票 | `status=empty`，无错误，保留排除原因 |
| 整体契约错误 | `status=failed`，同时返回 error，候选清空，`reason` 保存错误 |
| 报告版本 | schema 1；模型 artifact 独立使用 schema 2 |

报告保留信号日、目标交易日、生成时间、模型 ID/版本/SHA-256/训练区间、预算、股池总数、可计算数量、候选与排除项。候选保留 `rank/code/name/sector/close/change_pct`、五个评分字段 `base_score/model_score/base_rank/model_rank/blend_score`，以及信号日 `features` 快照。

## A｜行动：先校验，再计算特征和融合分

### 1. 校验范围与排除顺序

非法或重复股池代码、行情代码不属于股池、同一代码有多份行情，都会使整份初筛失败。其余逐股问题按下表顺序排除，因此同时违反多个条件时只记录先遇到的原因。

| 条件 | `excluded[].reason` |
| --- | --- |
| 没有对应行情 | `missing_data` |
| `History.Validate()` 不通过 | `invalid_history` |
| schema、复权口径或行情 `AsOf` 与请求不一致 | `invalid_or_stale_data` |
| 少于 65 根日线 | `insufficient_history` |
| 最后一根日期不是信号日 | `stale_or_suspended` |
| `strategy.Extract` 失败 | `invalid_or_insufficient_features` |
| 前 20 根低点非法，或模型原始输入不是有限数 | `invalid_numeric_input` |
| 有效股票排名超出预算 | `outside_budget` |

[History.Validate](../../internal/market/market.go)会拒绝乱序、重复日期、晚于自身 `AsOf` 的 K 线以及非法价格/成交量。`Analyze` 不负责裁剪未来行情：往有效输入追加信号日之后的 K 线，应被排除，不能期待函数忽略新 K 线后返回原排名。完整交易日、停牌和十年覆盖的校验由上游同步负责，65 根只表示此层的计算下限。

### 2. 特征单位与窗口

特征来自 [strategy.Extract](../../internal/strategy/features.go)、[indicators.Score](../../internal/indicators/indicators.go) 和初筛自己的 `priorLow20/touchRate20`。设信号日为末根索引 `t`，以下区间均包含两端，`MA20[t]` 为最近 20 根收盘均值。

| 特征 | 定义与单位 |
| --- | --- |
| `return1/return5/return10` | `100 × (close[t] / close[t-n] − 1)`，百分数数值 |
| `ma20_distance` | `100 × (close[t] / MA20[t] − 1)` |
| `ma20_slope` | `100 × (MA20[t] / MA20[t−5] − 1)` |
| `high20_distance` | `100 × (close[t] / max(high[t−20:t−1]) − 1)`，不含当日高点 |
| `low20_distance` | `100 × (close[t] / min(low[t−20:t−1]) − 1)`，不含当日低点 |
| `atr14_pct` | 最近 14 根真实波幅的算术均值除以当日收盘，再乘 100；真实波幅取 `high−low`、`abs(high−前收)`、`abs(low−前收)` 中最大值 |
| `volume_ratio` | 当日成交量除以前 5 根平均成交量；分母为 0 时为 0 |
| `rsi14` | Wilder 平滑 RSI，范围 0～100；全平为 50、仅上涨为 100 |
| `close_position` | `(close−low)/(high−low)`；当日高低相等时为 0 |
| `upper_wick` | `(high−max(open,close))/(high−low)`；当日高低相等时为 0 |
| `touch_rate20` | 最多 20 个已走完后续 3 根的历史锚点中，最高价触及锚点收盘 +1% 的比例，范围 0～1 |
| `relative_return5` | 当股 `return5` 减去本次全部有效股票的 `return5` 均值，单位为百分点 |

`touch_rate20` 的最晚锚点是 `t−3`，窗口为 `a+1` 到 `a+3`，因此允许窗口末根正好落在信号日。代码用 K 线索引而不是交易日历定位窗口，缺失交易日是否已被解释依赖上游数据契约。

```text
anchors = max(0, t−3−19) ... t−3
hit(a) = max(high[a+1:a+3]) / close[a] − 1 >= 0.01
touch_rate20 = 命中锚点数 / 有效锚点数
```

`trend_score` 由均线排列（0/15/30）、MACD（0/15/25）、RSI（0/5/12/20）、连续上涨天数（0/4/10/15）和量比（0/5/10）相加。具体阈值及 EMA/RSI 初始化以 `indicators.Score` 为准；替换指标库时必须核对这些初始化，不能只匹配指标名称。

### 3. 机会分和 logistic 模型

机会分起点为 `25 + 0.25 × trend_score`，应用以下调整后截断到 `[0,100]`。池均值在预算截断前计算。

| 条件 | 调整 |
| --- | --- |
| `ma20_slope > 0` | +10 |
| `return5 >` 有效池 `return5` 均值 | +10 |
| `close_position >= 0.65` | +10 |
| `1 <= volume_ratio <= 2.5` | +10 |
| `1 <= atr14_pct <= 4` | +10 |
| `ma20_distance > 10` 或 `return5 > 12` | −20，一次 |
| `upper_wick > 0.5` | −10 |

`12` 表示 12%，不能在这些条件里使用 `0.12`。规则分与正式策略有相似公式，但此处单独计算，不等于正式推荐结论。

[logistic_z artifact](../../internal/firststage/model.json) 固定以下 8 项顺序：

```text
z_atr14_pct, z_low20_distance, z_return5, z_rsi14,
z_touch_rate20, z_base_score, z_volume_ratio5, z_high20_distance
```

每个原始特征先在当日有效池上做横截面标准化，再使用 artifact 中的训练均值、尺度和系数：

```text
σ_j = sqrt(Σ(x_ij − 当日均值_j)² / n)
z_ij = 0                              若 σ_j=0
z_ij = (x_ij − 当日均值_j) / σ_j       其他情况
p_i = sigmoid(intercept + Σ coefficient_j × (z_ij − means_j) / scales_j)
```

总体标准差分母为 `n`，不是 `n−1`。机会分作为 `z_base_score` 进入模型；`return1/return10/trend_score` 虽保留在快照中，却不单独作为 logistic 输入。`p` 是模型分，文档和卡片不能据此宣称已校准的成功概率。

当前 artifact：schema 2，训练行数 26,123，训练日期 2026-01-14～2026-10-15，SHA-256 为 `8a833e8d124c94fdd1487ad614a01d263ea579f2859d641e4120b02fb34f9988`。[加载器](../../internal/firststage/model.go)在首次调用 `DefaultModel()` 时校验嵌入字节的哈希，并检查单份 JSON、未知字段、特征顺序、数组长度、有限数、正尺度、融合算子和权重和；校验结果由 `sync.Once` 缓存。生产计算不调用训练脚本或外部推理服务。

### 4. 当前 Rank-Gauss 的准确公式

机会分和模型分分别升序排列，以 0 起始位置计算同分中位百分位：

```text
r = (同分组起始位置 + 同分组结束位置) / 2 / (n−1)
```

`n=1` 时 `r=0.5`。注意，源码随后对这个已经落在 `[0,1]` 的 `r` 再做一次转换：

```text
u_base  = (base_rank  + 1) / (n + 1)
u_model = (model_rank + 1) / (n + 1)
blend_score = Φ(0.44 × Φ⁻¹(u_base) + 0.56 × Φ⁻¹(u_model))
```

这与直接计算 `Φ⁻¹(base_rank)` 不同，也与把原始 0 起始名次加一后除以 `n+1` 不同。例如 `n=95` 时，进入正态分位函数的数值只在 `[1/96,2/96]` 内；`n=1` 时最终融合分为 0.75。重建当前行为必须保留这个转换。若要改成其他 Rank-Gauss 定义，应单独变更算法并重新评估，不能仅改文档。

按 `blend_score` 降序、代码升序排序后取预算数量。同分代码只影响稳定展示次序，不影响同分百分位。

### 5. 报告接入与事后复盘

[selection.attachFirstStage](../../internal/selection/selection.go)在主报告计算后附加初筛报告。初筛错误保存在子报告中，不自动把主报告变成失败。[monitor 复盘入口](../../internal/monitor/first_stage_review.go)按交易日历生成截至评估日的 3 个交易日，读取对应历史初筛，利用候选和排除项还原当时股池。

[EvaluateHorizon](../../internal/firststage/review.go)输出 schema 3 复盘：默认统计输入候选前 30 项，同时保留全部候选结果。最高价触及涨幅为 `100 × (窗口最高价 / 信号日收盘 − 1)`；默认命中阈值为 1。

```text
top_hit_rate_pct    = 前30项命中数 / 前30项可评估数 × 100
candidate_recall_pct = 全部候选命中数 / 全池命中数 × 100
top_coverage_pct     = 前30项命中数 / 全池命中数 × 100
```

全池命中数为 0 时 `recall_available=false`，不能把默认数值 0 解读为召回失败。原报告无候选时为 `empty`；前 30 项没有可评估股票时为 `unavailable`。日期契约错误也返回 `unavailable` 和 error。

当前复盘有一处需要保留的限制：接口要求传入恰好 3 个递增日期，但 `reviewPrice` **没有逐日检查三根 K 线齐全**。只要窗口内存在有效高价/收盘，就可能被评估；`horizon_close` 取遍历到的最后一根有效窗口 K 线，未必是第三日收盘。复盘还使用评估时读取的复权历史，没有重新构造信号日当时的复权快照。因此，当前结果不能称为严格完整窗口、严格点时复权的收益验证。
