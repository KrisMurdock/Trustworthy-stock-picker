# 全市场低套牢扫描方案

核对基线：`feat/allmarket-trapped-scan`，2026-11-03。本文描述一个离线研究工具：读取独立的全市场日线库，复用套牢 v3 诊断，按上方套牢量升序输出全市场观察名单。它不进入日常选股、正式推荐、结构门控或通知投递。

## S｜情境：把套牢诊断从股池扩展到全市场

日常套牢信号只附加在 `leaders.yaml` 股池的排名和精排候选上，报告顺序仍由策略分决定。研究上还需要一个独立问题：在满足流动性和历史长度门槛的沪深股票中，哪些股票的 120 日上方套牢成交量占比最低？

这个问题不能直接使用主报告，因为主报告没有全市场行情和换手率；也不能只按“套牢量最低”排序，否则次新股、停牌股和低流动性股票会占据前面。因此工具先做覆盖率与资格过滤，再输出 Top N 和整体分布。

## T｜任务：冻结快照、资格门槛和可恢复的换手率缓存

### 输入

- `all-market.db` 中 `adjust="none"` 的不复权日线，使用 `stock_sync.as_of` 冻结同一数据日。
- 每只股票最近 120 个交易日用于套牢计算；读取两年日线用于判断上市和交易历史是否足够。
- 日度换手率和成交额来自搜狐或 BaoStock，只对通过资格过滤的股票抓取。
- 默认数据日为全市场库中覆盖至少 90% 股票的最新原始行情日，避免少量 `-codes` 刷新改变默认横截面。

### 默认资格门槛

| 条件 | 默认值 | 说明 |
| --- | --- | --- |
| 原始交易日数 | 至少 250 日 | 降低次新股和短历史样本对横截面的影响 |
| 最后交易日 | 必须等于数据日 | 排除数据日停牌或行情陈旧股票 |
| 20 日估算成交额 | 至少 2000 万元 | 使用不复权收盘价和换算股数估算，0 可关闭 |
| 风险警示名称 | 排除 `ST`、`*ST` 等 | 使用当前名称；不推断历史 ST 状态 |
| 套牢信号状态 | 只把非 `unknown` 纳入 Top | 换手率缺失、股本口径变化或样本不足明确剔除 |

### 计算

套牢计算完全复用 `strategy.AnalyzeTrappedSignalV3`：不复权价格、成交量换算为股数、低-收-高三角分布、按换手率逐日衰减、现价上方 5%/15% 分档和最大余数归一化。扫描器只改变输入范围和排序方式，不复制或放宽套牢公式。

候选按 `trapped_volume_ratio` 升序排列；比率相同按 20 日估算成交额降序、再按代码升序，避免零套牢股票只按代码截断。输出同时保留当前套牢区和三档价格区间，但“低套牢”不等于低估值、低风险或买入信号。

### 换手率缓存

- 缓存是代码到 `DailyMetricHistory` 的 JSON 映射，默认位于 `.scratch/allmarket-trapped/turnover-metrics.json`。
- 只有缓存覆盖全部正成交日时才复用；缺日、过期、校验失败或显式 `-refresh` 时重新抓取。
- 抓取成功后按批次原子写回，支持中断后继续；`-offline` 在缓存不完整时直接失败，避免研究结果悄悄混入不同日期。
- 单只股票抓取失败不会中止全市场；失败股票保留为 `unknown`，计入 `fetch_failures`。

## A｜行动：运行命令

```bash
set -a
. /etc/stock-watcher.env
set +a

go run ./cmd/trapped-scan \
  -as-of 2026-11-02 \
  -workers 2 \
  -top 50
```

常用参数：

```text
-data-dir PATH             数据目录；为空读取 STOCK_WATCHER_DATA_DIR
-require-cifs              强制数据目录为 CIFS
-as-of YYYY-MM-DD          固定全市场快照；为空取最新覆盖日
-top 50                    输出数量
-min-history-sessions 250  最低原始交易日数
-min-amount 20000000       20 日估算成交额门槛，0 关闭
-workers 2                 并行抓取数，1..8；默认 2，4 路曾触发 Sohu 503
-source sohu|baostock      换手率来源
-cache PATH                换手率缓存
-refresh                   忽略并替换缓存
-offline                   只使用已有缓存，缺数据即失败
-limit N                   只扫描前 N 只，仅用于联调
-json                      把完整结果 JSON 输出到 stdout
```

默认输出：

- `.scratch/allmarket-trapped/top50.json`：完整结果，包含资格过滤统计、状态分布、套牢量分桶和 Top N。
- `.scratch/allmarket-trapped/turnover-metrics.json`：可恢复的换手率缓存。

## R｜结果与边界

结果字段：

| 字段 | 含义 |
| --- | --- |
| `history_from` | 读取全市场原始日线的起始日期；默认数据日前两年 |
| `universe_stocks` | 数据日有成功原始行情的股票数 |
| `eligible_stocks` | 通过历史、停牌、名称和流动性门槛的股票数 |
| `scanned_stocks` | 实际进入计算的股票数；仅在 `-limit` 时小于 eligible |
| `signals` / `valid_signals` / `unknown_signals` | 套牢计算总数、有效数和未知数 |
| `fetched_metrics` / `cache_hits` / `fetch_failures` | 换手率抓取数、缓存命中数和失败数 |
| `status_counts` | `none`、`watch`、`triggered`、`unknown` 分布 |
| `distribution` | 有效信号按套牢量 0-5%、5-10%、10-20%、20-30%、30-50%、50-100% 分桶 |
| `top` | 按套牢量升序的候选，包含当前套牢区和三档区间 |

边界：

- 这是成交量代理，不是真实持仓成本；低套牢量不代表没有解套压力。
- 股本校验仍是成交量与换手率反推的代理口径，不能替代正式除权、送转和股本变动事件。
- 全市场结果受数据日覆盖率、停牌、上市时间和流动性门槛影响；不同参数下的 Top 不可直接比较。
- 工具只读 `all-market.db`，不写行情库、不修改报告、不发送消息，也不自动进入公众号。
- 结果应称为“低套牢观察池”，不能表述为推荐名单、成功概率或收益承诺。
