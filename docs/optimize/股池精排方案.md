# 股池精排方案

核对日期：2026-10-29。源码基线：`3e2510b`。本文记录当前生产内置排序方案、离线分数接口和辅助树模型，供复现或重建使用；没有据此确认线上模型文件或部署版本。

## S｜情境：在初筛候选内融合多路证据

初筛最多保留 95 只研究候选。精排在这个集合内融合初筛顺序、四路离线决策分和 ATR 风险扣罚，输出最多 10 只研究候选。它不从初筛池外递补，不生成可执行交易，也不改变正式推荐的样本、收益和风险门槛。

生产 Go 进程只读取已经落盘的模型分数。Python 推理脚本属于独立的离线产物生成流程，不在 Go 排序进程中运行。[selection.Run](../../internal/selection/engine.go)在进入算法前加载并冻结模型快照；[attachSecondStage](../../internal/selection/selection.go)把精排结果附在 `second_stage` 中。

## T｜任务：把输入、降级和排序顺序固定下来

[secondstage.Analyze](../../internal/secondstage/analyze.go) 的实际接口是：

```go
Analyze(first firststage.Report, opts Options) (Report, error)
```

`Options` 包含日期、Top N、推送开关、融合计划、模型快照和生成时间。文件读取由 `LoadModel/LoadModels` 完成，排序函数消费内存中的 `ModelInput`。固定 `Now` 才能复现生成时间。

| 约束 | 当前实现 |
| --- | --- |
| 初筛输入 | schema 1、状态 `ok`、候选非空，`AsOf/Target` 与精排请求一致 |
| 输入失效 | `status=failed`、error 与 `reason`，候选清空；不退回全股池 |
| 生产 Top N | 10；配置范围 1～100；直接调用 `Analyze` 时 `TopN<=0` 会补为 10 |
| 模型契约错误 | 重复/非法模型名、非法状态、`ok` 但无分数、数值越界等返回失败 |
| 文件不可用或覆盖不足 | 用中性分补缺，成功报告仍为 `ok`，另设 `degraded=true` |
| 输出版本 | 报告 schema 1，离线文件 schema 1；辅助树另有模型 schema 与特征版本 |

配置默认值与生产内置值不同，见 [DefaultSecondStage](../../internal/config/second_stage.go) 和 [Builtin](../../internal/config/builtin.go)：

| 配置 | 通用默认值 | 生产内置值 |
| --- | --- | --- |
| 计算/推送 | 均关闭 | 均启用 |
| `blend_id` | `blend_50_50` | `risk_all20_local035_eta1` |
| 初筛权重 | 0.5 | 0.2 |
| 离线模型权重 | JEV 0.5 | JEV、Laya official、Laya multilingual、Chinese Decision 各 0.2 |
| `group_size` | 15 | 5 |
| 校准 | `none` | `local`，参数 0.35 |
| ATR 风险系数 | 0 | 1 |

初筛权重允许为 0；每个离线模型权重必须大于 0 且不超过 1，总和与 1 的误差不能超过 `1e-9`。模型名是受限字符串，并非四个名称的硬编码白名单。启用配置时组大小为 1～100，校准参数和风险系数为 `[0,1]`。包级空计划会回退到默认融合，缺省组大小会补为 15，不能把这些包级补值当成生产配置。

## A｜行动：加载分数，计算组内百分位，再扣风险

### 1. 四路离线决策分的来源

默认生成入口 [generate_daily.py](../../scripts/secondstage/generate_daily.py) 使用组大小 5，分别调用下列适配器。各单独脚本的默认组大小仍为 15，手工运行时需要显式保持一致。

| 模型键 | 当前脚本指定的模型或仓库 | 适配器 |
| --- | --- | --- |
| `jev` | 本地 `Qwen3-0.6B`，读取选项字母 logits 后 softmax | [jev_scores.py](../../scripts/secondstage/jev_scores.py) |
| `laya_official` | `convaiinnovations/laya` | [laya_scores.py](../../scripts/secondstage/laya_scores.py) |
| `laya_multilingual` | `convaiinnovations/laya-multilingual` | 同上，选择 multilingual checkpoint |
| `chinese_decision` | `quincyqiang/chinese-decision-0.8b`，按模型配置温度校准选项 logits | [chinese_decision_scores.py](../../scripts/secondstage/chinese_decision_scores.py) |

这些名称说明代码配置，不证明机器上模型权重与某个远端版本完全一致。`deepseek` 是 `generate_daily.py --deepseek` 显式启用的额外离线支路，不在当前内置融合权重中。

四路使用同一组信号日事实，代码和名称仅用于生成器关联行；发给模型的候选改为组内 `C1/C2/...`。模型请求保留信号日期，不包含股票代码、名称、行业或未来标签。

| 请求字段 | 初筛特征 | 小数位 |
| --- | --- | --- |
| `close_vs_ma20_pct` | `ma20_distance` | 1 |
| `ma20_slope_5d_pct` | `ma20_slope` | 1 |
| `return_5d_pct` | `return5` | 1 |
| `relative_strength_5d_pct` | `relative_return5`，兼容 `rel_return5` | 1 |
| `rsi14` | `rsi14` | 0 |
| `close_position` | `close_position` | 2 |
| `volume_ratio` | `volume_ratio`，兼容 `volume_ratio5` | 2 |
| `distance_to_20d_high_pct` | `high20_distance` | 1 |
| `atr14_pct` | `atr14_pct`，兼容 `atr14` | 1 |
| `upper_wick` | `upper_wick` | 2 |

字段单位沿用[初筛方案](股池初筛方案.md)：百分数数值与 `[0,1]` 形态比例分开。问题要求从同组中选择“3 日延续形态更强且反转风险可接受”的一项。每组按原顺序、逆序和旋转一位的选项顺序推理，映射回候选后取均值。输出表达的是组内选择证据，不能解释为未来上涨成功率。

`adjacent15` 沿用历史字段名，生产组大小为 5 时仍使用该名。两个输出字段的具体语义需分开：

| 字段 | JEV | Laya / Chinese Decision |
| --- | --- | --- |
| `adjacent15` | 当前配置组内三次 softmax 概率的均值 | 当前配置组内三次返回概率的均值；适配器验证范围和正总量，不强制总和等于 1 |
| `full15_top12` | 额外对初筛前 `min(15,n)` 只重推；把原顺序前 `min(12,n)` 只的分数重新归一化，其余为 0 | 使用首个配置组的 `adjacent15`，把该组原顺序前 `min(12,group_size)` 只重新归一化，其余为 0；生产组大小 5 时就是前 5 只 |

`full15_top12` 中的前 12 是初筛顺序，不是按模型分取最高 12 只。它保留在证据中并供辅助树使用，不参与当前融合排序。

离线分组至少需要 2 只。尾组只有 1 只会先被跳过，随后因覆盖不全而使该日期生成失败；不能把 95/5 的正常整除情形外推到任意候选数。推理异常、选项缺失或上下文截断不补默认分。每个模型完成整日计算后原子写入 JSON，默认分只在 Go 消费阶段使用。

### 2. 文件格式、校验和冻结边界

模型文件路径由 [selection/second_stage.go](../../internal/selection/second_stage.go) 拼接：

```text
<data_dir>/state/secondstage/<model>/<as-of>.json
```

只有 `jev` 在新路径不存在时尝试旧路径 `state/jev/<as-of>.json`；新路径存在但内容损坏时不尝试旧文件。

```json
{
  "schema_version": 1,
  "as_of": "2026-10-28",
  "scores": {
    "sz000001": {"adjacent15": 0.2, "full15_top12": 0.1}
  }
}
```

这是格式示例，不是行情或真实模型结果。文件另允许 `model` 元数据对象和 `prompt_version` 字符串。

| `ModelInput.status` | 来源 | 消费行为 |
| --- | --- | --- |
| `ok` | 单份合法 JSON、schema 1、日期匹配、分数非空、两项分数均在 `[0,1]` | 仅使用覆盖到的初筛候选；额外代码不扩张候选池 |
| `missing`（`ModelStatusNil`） | 空路径，或任意 `os.ReadFile` 错误，包括不存在、权限不足 | 所有候选使用中性分，标记降级 |
| `invalid`（`ModelStatusBad`） | JSON/未知字段/多文档/schema/日期/分数范围校验失败 | 所有候选使用中性分，标记降级 |

`ValidateModelInputs` 还拒绝空白代码键、重复模型，以及非 `ok` 状态夹带分数。文件加载与内存校验是两层不同边界：例如加载器未拒绝的空白代码键，会在内存校验时使计算失败。

当前加载器不验证 `model` 中的底座版本、生成组大小或特征摘要，也不校验离线文件哈希；同一天的文件可能来自不同参数。Go 框架会把所读模型分数冻结进算法输入，但不能据此推断文件来自同一次生成运行。重建兼容此接口时应保留现有行为；若增加版本或参数一致性检查，需要作为显式契约变更。

### 3. 百分位与 local 校准

精排先把初筛 `blend_score` 在**入围候选集合**上重新计算百分位，不直接把初筛原分作为加权输入。高分对应高百分位；升序同分组占用的 0 起始位置为 `a...b` 时，百分位是 `(a+b)/2/(n−1)`，单项集合为 0.5。

生产分组按 `(first_stage_rank−1)/5` 取整数部分：1～5、6～10 等依次分组。若包级调用给的 rank 不为正，代码才使用数组位置分组。每个模型只对“同组且实际有该模型分数”的候选，以 `adjacent15` 计算百分位；未覆盖者不进入该模型百分位的分母。

```text
prior_g = mean(组 g 内所有初筛候选的 first_stage_percentile)

有该模型分数：calibrated = clamp(prior_g + 0.35 × (percentile − 0.5), 0, 1)
缺该模型分数：percentile = 0.5，calibrated = 0.5，present = false
```

缺失项**不经过 local 校准**。因此，“已覆盖且组内百分位恰为 0.5”和“未覆盖”是两种结果：前者校准后等于组先验，后者固定为 0.5。这一差异由 `TestAnalyzeMissingModelRemainsNeutralWithLocalCalibration` 锁定。

### 4. 融合和风险扣罚

生产计划的最终公式是：

```text
weighted_score = 0.2 × first_stage_percentile
               + 0.2 × calibrated_jev
               + 0.2 × calibrated_laya_official
               + 0.2 × calibrated_laya_multilingual
               + 0.2 × calibrated_chinese_decision

atr_percentile = ATR14Pct 在全部初筛候选上的同分中位百分位
risk_penalty = 1.0 × atr_percentile
blend_score = weighted_score − risk_penalty
```

ATR 百分位不按 5 只小组计算。最终分允许为负，代码不截断到 `[0,1]`；一般范围为 `[-risk_eta,1]`。全部模型缺失时仍会返回受初筛和 ATR 影响的降级排名，不能标为“四模型一致看好”。

排序键依次为 `blend_score` 降序、`first_stage_rank` 升序、代码升序。只保留前 `min(top_n,n)` 项，其余记 `outside_top_n`。报告同时保留各模型状态/覆盖数、`degraded`、每项原始分/百分位/校准分/`present`、扣罚前后分数和缺失原因；JEV 缺失原因为 `jev_missing`，其他模型为 `model_missing:<name>`。

### 5. 辅助树模型：固定特征，独立于排序分

[second_stage_gbdt_v1](../../internal/secondstage/model.json) 编译进二进制。模型 schema 1、特征版本 v1，训练区间 2026-09-03～2026-09-21，1,885 行，SHA-256 为 `21cb6c2a19706381cdb0ce2598ceda743b81227b22391cb5f92ba429d9d4e960`。[加载器](../../internal/secondstage/model.go)检查哈希、特征顺序、有限参数及树节点可达性/环路；错误会让精排失败，不能省略模型加载。

v1 的 27 项顺序由 [features.go](../../internal/secondstage/features.go) 固定：

```text
first_stage_blend, first_stage_rank, first_stage_base_rank,
first_stage_model_rank, first_stage_base_score,
jev_adjacent15, jev_adjacent15_pct, jev_adjacent15_rel,
jev_full15_top12, jev_full15_top12_pct, jev_present, jev_group_max,
return1, return5, return10, relative_return5, ma20_slope, ma20_distance,
atr14_pct, rsi14, volume_ratio, close_position, upper_wick,
high20_distance, low20_distance, touch_rate20, pool_return5
```

这些字段有几个不能按名字猜测的细节：

- `first_stage_rank` 是 `(初筛名次−1)/max(n−1,1)`，不是 1～95 的整数名次。
- 树的 JEV 统计始终按 **15 只**分组，独立于生产融合的 5 只分组。`jev_adjacent15_rel` 为该股分数除以组内最大分；`full15_top12_pct` 只在首个 15 只组计算。
- JEV 缺失时原始分和自身百分位等查不到的字段为 0，`jev_present=0`；若同组其他股票有分，`jev_group_max` 仍可非零。这不是融合阶段的中性 0.5 填充。
- `pool_return5` 是**入围初筛候选**的 5 日收益均值；快照中的 `relative_return5` 则来自初筛截断预算前的有效全池，两者分母不同。

预测为 `base + learning_rate × Σ tree(values)`，当前输出截断到 `[-10,20]`，单位是百分点。JSON 字段全名为 `predicted_max_high_return_pct`，描述未来 3 日最高价相对信号日收盘的最大涨幅预测。这个值不进入 `weighted_score` 或 `blend_score`；预测失败仍会使本次计算失败。

代码支持 v2 在 v1 后追加 4 项，但当前 artifact 未启用：`rank_jump_adjacent15`、`geo_blend_jev`、`harmonic_blend_jev`、`return_to_atr_ratio`。前三项分别为教师百分位与 `1−rankPosition` 的差、初筛融合分与教师百分位的几何均值和调和均值，JEV 缺失时为 0；最后一项始终为 `return5/max(atr14_pct,0.5)`。

### 6. 重算和发布的边界

`attachSecondStage` 保存精排子报告，包括失败状态；函数不把该 error 直接上抛为主报告失败。[RecomputeSecondStage](../../internal/selection/selection.go)保留行情和初筛，重读当前离线文件，重算精排并刷新阶段判断；若旧结果未降级而新结果降级，返回 error。它还更新报告 ID、清空 Revision，后续持久化和是否发布由调用方负责。

该函数的保护条件只检查“健康转降级”，不能扩大解释为所有失败结果都会被它拒绝。包级函数本身没有请求超时或取消参数；行情期限、离线推理超时和投递窗口分别由外层流程管理。
