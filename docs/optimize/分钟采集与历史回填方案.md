# 分钟采集与历史回填方案

核对基线：`33ab655`，2026-10-29。本文记录当前原生 Go 分钟采集、历史补齐和读取契约。文中的验收命令是复现入口，不代表本次已运行或线上已验证。

## S｜情境：实时窗口不足以支撑长期研究

腾讯分钟接口每次最多返回 640 根。常驻进程需要更新正在形成的 K 线、盘后核对当天数据；预测训练和实验则要读取更长的本地历史。两条写入路径共用 `market.db` 的原生 5 分钟序列，但更新规则不同：实时采集替换返回窗口内的记录，历史回填只补缺少的时间戳。

[分钟监控](../../internal/intraday/monitor.go)独立于日线发布门槛；[历史回填](../../cmd/stock-watcher/backfill_minutes.go)是显式 CLI 作业。回填成功不代表分钟监控完成当日校准，也不会自动生成报告或发送通知。

## T｜任务：保留时间、完成状态和写入边界

| 对象 | 当前契约 |
| --- | --- |
| 实时来源 | 腾讯原生 5 分钟，不调用日线多来源回退链 |
| 历史来源 | BaoStock 或新浪；`auto` 按请求范围选择一个来源，不是失败后自动切源 |
| 时间 | 上海时区，以 bar 结束时间标记；上午 09:35～11:30，下午 13:05～15:00 |
| 完成状态 | `Final` 来自采集时的观测，不允许只因读取时间变晚而把旧记录标为完成 |
| 存储 | 只保存 5 分钟；15/30/60 分钟读取时聚合，价格用百万分之一元整数 |
| 完整性 | 实时按目标时间逐个检查应有的 5 分钟槽；完整交易日共 48 根 |
| 写权限 | CLI 使用数据目录单写进程锁；缺目录、只读目录或要求 CIFS 时挂载失效，不能本地兜底 |
| 失败 | 单股上游错误记录状态后继续；取消和存储错误终止本轮 |

源码入口是 [CLI](../../cmd/stock-watcher/main.go)、[运行时](../../runtime/runtime.go)、[分钟协议与聚合](../../internal/market/intraday.go)、[分钟存储](../../internal/storage/intraday.go)及[归档导入](../../internal/storage/minute_import.go)。

## A｜行动：实时校准与历史补齐分别执行

### 1. 命令、默认值与覆盖

`run` 在 `intraday.enabled=true` 时启动分钟循环；`sync-intraday` 只执行当前时刻的一轮，禁用时返回错误，不接受 `-as-of`。`backfill-minutes` 独立于实时开关，按日期补历史。

| 配置 | 默认值与有效范围 | 环境变量 |
| --- | --- | --- |
| `intraday.enabled` | `true` | `STOCK_WATCHER_INTRADAY_ENABLED` |
| `poll_interval` | `1m`；30s～5m | `STOCK_WATCHER_INTRADAY_POLL_INTERVAL` |
| `request_interval` | `350ms`；350ms～10s | `STOCK_WATCHER_INTRADAY_REQUEST_INTERVAL` |
| `workers` | 3；1～8 | `STOCK_WATCHER_INTRADAY_WORKERS` |
| `calibration_at` | `15:10`；15:05～23:00 | `STOCK_WATCHER_INTRADAY_CALIBRATION_AT` |
| `tencent_endpoint` | 腾讯 `mkline` 接口 | `STOCK_WATCHER_INTRADAY_TENCENT_ENDPOINT` |
| `request_timeout` | 10 秒，共用请求超时 | `STOCK_WATCHER_REQUEST_TIMEOUT` |

端点仅接受 HTTPS 或回环 HTTP，不得含凭证、预置查询或 fragment；关闭分钟功能时跳过该组字段校验。定义见 [intraday.go](../../internal/config/intraday.go)，覆盖映射见 [environment.go](../../internal/config/environment.go)。当前 `require_cifs` 默认 `false`；共享盘部署必须显式启用 `STOCK_WATCHER_REQUIRE_CIFS=true`。

回填参数如下：

| 参数 | 行为 |
| --- | --- |
| `-as-of` | 默认最近已完成交易日；拒绝未来、非交易日或日历范围外日期 |
| `-from` | 包含起点；省略时取配置日历内最近至多 200 个交易日 |
| `-codes` | 逗号分隔股池代码，去重；省略为整池，池外代码拒绝 |
| `-workers` | 默认 3，范围 1～8，独立于实时 worker 数 |
| `-provider auto` | 范围不超过 104 个交易日用新浪，否则 BaoStock |
| `-provider sina` | 超过 104 个交易日拒绝；`baostock` 不受这个来源限制 |
| `-reference-dir` | fetch 模式只读参考库，以已有日线确定应有交易日 |
| `-import-from` | 从 staging 读取已完成分钟记录，不访问行情网络；不能与 `-reference-dir` 同用 |

### 2. 实时调度和 `Final`

`Run` 每 15 秒检查一次是否有到期任务，真正的请求频率由每股持久化的 `AttemptAt` 和 `poll_interval` 决定。非活跃时段最短重试间隔为 5 分钟，新到期的盘后校准可绕过一次冷却。

[Schedule](../../internal/intraday/monitor.go)按以下规则算目标结束时间：

1. 上午 09:30～11:29、下午 13:00～14:59，目标为当前所在 5 分钟区间的结束点，`Active=true`。
2. 午休目标为 11:30；当日收盘后目标为 15:00。
3. 盘前、周末或假日使用最近已完成交易日的 15:00。
4. 当日到 `calibration_at`，或目标日早于当天，进入校准；已校准该日的非活跃任务跳过。

首次成功采集前及每次校准请求 640 根，其余请求 64 根。所有 worker 共用实时客户端节流器。客户端把请求开始时间作为 `FetchedAt`，只有 `End <= FetchedAt - 10s` 才标记 `Final=true`，避免刚结束的窗口仍被上游修订。

响应必须匹配股票代码、schema 1、`source=tencent`、`period=base_period=5`、`adjust=none`、`volume_unit=provider_raw`；时间递增，OHLC 和成交量有限且合法。配置日历起点前的历史会过滤，覆盖范围内的非交易日或超范围日期使本次响应失败。

### 3. 状态、校准和事务

每股状态写入 `intraday_sync`，与本次有效 K 线同事务保存：

| 状态 | 触发条件 | 数据处理 |
| --- | --- | --- |
| `failed` | 网络/协议错误、身份或数据校验失败 | 只更新尝试和原因，保留已有 K 线及上次成功采集时间 |
| `stale` | 最后一根结束时间早于目标 | 保存合法响应，但不校准 |
| `partial` | 非活跃时最后一根未完成，或目标之前缺少分钟槽 | 保存合法响应，但不校准 |
| `ok` | 目标覆盖及槽位检查通过 | 校准阶段且最后一根 `Final` 时记录 `calibrated_date` |

原因包括 `source_unavailable`、`invalid_source_data`、`http_<状态码>`、`latest_bar_missing`、`awaiting_closed_bar` 和 `intraday_gaps`；不是每种本地校验错误都会归入 `invalid_source_data`，该分类取决于错误是否为 `market.DataError`。

盘中 `ok` 可以包含正在形成的最后一根。完整盘后校准要求当天 48 个槽位齐全且最后一根完成；`completeDay` 本身检查时间戳，不逐根断言 `Final`，当前腾讯解析器的完成标记随时间有序。

实时保存先删除响应首尾时间之间的旧记录，再插入本次窗口，因此上游删除的中间 bar 不会残留。窗口之外的旧历史及更晚记录保留；倒序的尝试时间或响应时间被拒绝。整股事务失败不会留下半个窗口。

### 4. 读取与聚合

15/30/60 分钟按上午、下午分别分组，不跨午休。聚合取首开、最高、最低、末收及成交量之和；只接受连续且起点正确的基础序列。

历史不完整分组省略；序列最后正在形成的分组可以返回连续前缀，但 `Final=false`。完整分组还必须所有基础 bar 都完成才置 `Final=true`。读取时不会借助当前时间把旧前缀改成已完成。`ValidateMinutePair` 通过元数据和逐值重算检查 5 分钟与派生周期是否来自同次观测。

[只读分钟接口](../../internal/dashboard/handler.go)接受股池代码与 `period=5|15|30|60`；页面展示最近窗口，研究读取[日期范围接口](../../internal/storage/minute_range.go)中的本地积累数据。长范围读取不会触发补下载。

### 5. 回填来源与增量导入

BaoStock 使用原生 TCP，每页 400 根、每页新会话，重试重新建会话；范围和条数有上限。新浪使用已有 K 线客户端。回填 worker 各自拥有客户端，因此其 `market.request_interval` 是每个客户端的节流，不能解释为整个回填进程的统一请求间隔。

[MinuteArchive](../../internal/market/baostock_minutes.go)为 schema 1，来源仅 `baostock/sina`，5 分钟、不复权、全部 `Final=true`，成交量为 `shares` 或 `provider_raw`。导入时将股数转换为腾讯原始口径：科创板保留股数，其余除以 100。最多接受 `20*366*48` 根。

`ImportMinuteArchive` 每股一笔事务，只补不存在的时间戳。已有记录即使未完成或价格冲突，也不会被回填覆盖；匹配记录计入 `existing`，冲突计入 `overlap_mismatch`。比较容差为价格 0.001 元、成交量 `max(0.5, abs(归档量)*1e-6)`，且完成标记必须相同。

回填不会更新 `intraday_sync`。数据表没有逐条来源字段；staging 导入用 `source=baostock`、`volume_unit=provider_raw` 构造归档，不保留最初供应商身份。后续实时响应仍可替换与这些历史记录重叠的窗口。

覆盖统计以本地指定复权日线出现的交易日为基础，再加入本次导入结果中配置日历内已有分钟的日期。fetch 前仅当应有日期非空、且目标库每个应有日恰好 48 根完成记录时跳过该股。

当前统计有两个需要读者保留的限制：`partial_sessions`（1～47 根）单独存在时仍可能返回 `status=complete`；只有零根的 `missing_sessions` 才把该股设为 `incomplete`。`overlap_mismatch` 也不会单独使命令失败。因此验收需单独要求缺日、部分日和冲突计数符合预期，不能只看退出码。

### 6. staging 与操作顺序

以下是操作模板；日期、股池和目录需替换为实际值。先创建独立 staging 数据目录并初始化，生产目录只作为只读覆盖参考：

```bash
mkdir -p /tmp/stock-watcher-minute-stage
STOCK_WATCHER_DATA_DIR=/tmp/stock-watcher-minute-stage STOCK_WATCHER_REQUIRE_CIFS=false ./bin/stock-watcher init
STOCK_WATCHER_DATA_DIR=/tmp/stock-watcher-minute-stage STOCK_WATCHER_REQUIRE_CIFS=false ./bin/stock-watcher backfill-minutes -from 2026-09-01 -as-of 2026-10-28 -codes sz000001 -reference-dir /path/to/production-data
```

导入生产目录前停止持有同目录写锁的 `run`，备份数据库并关闭写连接；使用生产环境变量执行：

```bash
./bin/stock-watcher backfill-minutes -from 2026-09-01 -as-of 2026-10-28 -codes sz000001 -import-from /tmp/stock-watcher-minute-stage
```

首次 staging 没有日线时应提供 `-reference-dir`，否则缺失交易日缺少参考依据。当前 BaoStock 回填构造器未把 `market.baostock_address` 赋给客户端，不能用该环境变量声称 CLI 回填已连接 mock 地址；协议测试可以直接注入客户端地址。
