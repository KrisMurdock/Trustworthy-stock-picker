# 套牢信号方案

核对基线：`d8e1018`，2026-11-02。本文描述精排候选的上方套牢压力诊断，以及它在公众号文章中的展示方式。该诊断不参与正式推荐、机会分、结构门控或交易执行。

## S｜情境：给精排候选增加上方成交压力说明

精排会输出下一交易日的研究候选，但原始排序只消费价量特征和离线分数，没有直接回答“现价上方是否还有一批近期成交、等待解套的筹码”。本方案用日线 OHLCV 构造一个可复现的成交量加权代理，把每只候选的套牢压力附在报告和公众号文章中。

它解决的是“上方成交密集区有多重、离现价多远”的描述问题，不预测解套、回落或未来收益。真实持仓成本、股东结构和逐笔换手没有进入日线契约，因此不能把成交量代理写成精确套牢盘。

## T｜任务：固定输入、阈值和未知状态

[AnalyzeTrappedSignal](../../internal/strategy/trapped.go) 的输入是策略同口径的日线 `[]market.Bar`，输出版本化 `TrappedSignal`。信号随 `strategy.Candidate` 保存为 `trapped_signal`，字段包括状态、样本数、套牢量占比、加权成本、成本带、距现价空间和区间回撤。

| 项目 | 当前口径 |
| --- | --- |
| 回看窗口 | 最近 120 个交易日；超过时只取末尾 120 根 |
| 最低样本 | 至少 60 根有效且成交量大于 0 的日线 |
| 单日价格 | 典型价 `(high + low + close) / 3` |
| 权重 | 当日 `volume_raw`；同股内部比较，不跨来源换算 |
| 上方套牢量 | 典型价高于信号日收盘的成交量 / 窗口总成交量 |
| 加权成本 | 上方成交量的成交量加权典型价 |
| 成本带 | 上方成交量分布的 20%～80% 加权分位 |
| 距现价 | `(加权成本 / 信号日收盘 - 1) × 100%` |
| 区间回撤 | `(信号日收盘 / 窗口最高价 - 1) × 100%` |

状态规则在样本和成交量有效后计算：

| 状态 | 条件 |
| --- | --- |
| `triggered` | 上方套牢量 ≥ 30%，且加权成本高于现价 ≥ 2% |
| `watch` | 上方套牢量 ≥ 20%，且加权成本高于现价 ≥ 1% |
| `none` | 未达到观察阈值；现价上方没有成交时套牢量为 0 |
| `unknown` | 日线少于 60 根、没有正成交量或数据无效 |

`unknown` 只表示无法可靠计算，不能当作“没有套牢”。阈值是 v1 诊断常量，不进入正式推荐门槛；后续调整必须新版本化并补回归，不能静默改变历史报告含义。

## A｜行动：计算结果进入报告和公众号

1. [selection.attachTrappedSignals](../../internal/selection/trapped.go)在精排完成后遍历 `report.Ranking`，只使用代码相同且复权口径一致的日线。
2. 结果写入 `Candidate.Trapped`，随报告 JSON 持久化；报告 ID、冻结输入和重放语义沿用既有候选结构。
3. 第二层公众号文章在候选介绍前增加一行“套牢盘诊断”，按精排名次输出：`名次 + 触发/观察/无/缺 + 套牢量 + @加权成本`。例如 `1触发36%@16.10 2观察24%@15.60 3无`。
4. `无` 表示未达到观察阈值，`缺` 表示数据不足；`@` 后为加权成本，价格精度保留两位小数。文章同时给出触发、观察阈值，并注明“仅提示上方成交压力，非交易信号”。
5. 整体结论会把触发或观察列为共同风险之一，但不改变“正式推荐/观察”的既有判断。
6. 公众号正文有 20,000 字符上限。当前实现用一行摘要承载全部候选结果；完整成本带、回撤和原因保留在报告 JSON 中，不在正文重复展开。

## R｜结果与边界

- 成功路径：120 个交易日中 80 天在现价上方、30 天当前价格，套牢量为 66.7%，加权成本 12.00、距现价 +20%，状态为 `triggered`。
- 边界路径：25% 套牢量为 `watch`；无上方成交为 `none`；59 根日线或无正成交量为 `unknown`。
- 公众号路径：每只文章候选都有摘要 token；十只股票同时触发且成本为四位数时，渲染后仍低于 20,000 字符。
- 不承诺：该信号不是实际持仓亏损，不是解套概率，不构成买卖建议，也不改变正式推荐或风险门槛。
