# 冻结报告复盘方案

核对日期：2026-10-29。源码基线：`33ab655`。本文记录当前只读复盘投影、统计口径及网页接口。复盘结果来自已保存报告与后续本地行情，不能据此确认线上数据完整或策略具有未来收益。

## S｜情境：保留当时判断，再观察后续路径

日推报告保存的是信号日的候选、排名、推荐标记、策略参数和输入。后续行情到达后，`internal/review` 用这些冻结事实重建参考成交结果，供 `/review` 页面及 AI 证据问答读取。它不重跑选股、不修改排名、不保存新报告，也不发送通知。

这里有两个时间边界：报告判断冻结在生成时，事后行情仍取当前本地可用窗口。同一 `revision` 在后续交易日可以从“未成熟”变成“已成熟”；行情修订或日历变化也可能改变投影。它与要求同构建重算冻结算法输入的 `replay` 命令用途不同。

主要边界见 [review.go](../../internal/review/review.go)、[网页加载适配器](../../internal/dashboard/review_loader.go)、[存储查询](../../internal/storage/review.go) 和 [成交模拟器](../../internal/strategy/trade.go)。

## T｜任务：固定输入、状态及统计分母

服务对外只有两个读取方法：

```go
Day(ctx context.Context, asof, revision string) (Day, error)
Event(ctx context.Context, asof, code, revision string) (Event, error)
```

`Event` 先执行整日投影，再从结果中选择代码；它没有独立的单股增量计算缓存。调用者必须提供 `Loader`，不能在服务内部下载缺失行情。

| 输入或输出 | 当前契约 |
| --- | --- |
| 信号日期 | 必须与加载报告的 `AsOf` 相同 |
| 修订 | 指定时读 `report_archive`；省略时读该日看板报告 |
| 候选集合 | 优先用完整 `report.Ranking`；为空时从 `Selected` 转为推荐候选 |
| 排名 | 保留候选 `Rank`；为 0 时用数组中 1 起始位置 |
| 执行价格 | 冻结输入里的 `Raw` 信号日 + 当前 `adjust=none` 后续窗口 |
| 策略参数 | 报告 `Provenance.Parameters`，不使用当前运行配置覆盖 |
| 输出版本 | 复盘 `Day.schema_version=1`；与报告 schema、数据库 schema 分开 |
| 展示计划 | 原报告候选的 `reference_plan`；实际模拟按冻结参数与后续开盘重新生成计划 |
| 持久化 | 读取时计算，不建立复盘结果表 |

## A｜行动：从报告修订读到事件聚合

### 1. 修订索引与兼容范围

当前 [MarketDB](../../internal/storage/marketdb.go) schema 为 **6**。复盘迁移给 `report_archive` 增加 `as_of`、`generated_at`、`schema_version`，建立 `(as_of, generated_at)` 索引；回填解析旧 JSON，但不改写归档 payload。损坏 payload 保留原状，不纳入有效修订列表。

`ListReportRevisions` 返回指定日期的可解析记录，按生成时间升序、再按 revision 字典序排列。网页自行倒序展示修订。不能把列表最后一条直接等同于默认报告：未传 revision 时，加载器调用的是 `LoadDashboardReport(asof)`。

服务拒绝报告日期与请求日期不一致。HTTP revision 必须是 64 位小写十六进制；报告归档读取还校验内容身份，相关兼容测试见 [storage/review_test.go](../../internal/storage/review_test.go)。只有一个报告修订，也不代表已有完整冻结原始行情。

以下报告保留候选、理由与证据，但全部事件标为 `unsupported`：

- `report.Version == 1`，或 `report.Strategy != "short_horizon_v1"`，原因为 `legacy_report_has_no_execution_review`。
- 缺失或无法解析冻结参数，策略参数校验失败、持有期限非法。
- 报告声明了 `ConfigID`，但参数重新计算的配置摘要不匹配。

当前判断没有写成“仅接受报告 schema 2/3”的白名单；不能据此宣称未来任意 schema 都已兼容。无候选时直接返回空事件列表，不继续检查参数或读取后续行情。

### 2. 哪些事实冻结，哪些仍会变化

| 数据 | 读取来源 | 对结果的影响 |
| --- | --- | --- |
| 排名、推荐、理由、风险、结构门控 | 选定报告 payload | 保留当时判断，不按新行情修正 |
| 费用、滑点、预算、持有期限、开盘偏离门槛 | 冻结 `Provenance.Parameters` | 模拟与当时报表参数一致 |
| 信号日 OHLCV | `InputID` 对应冻结输入的 `Raw` | 不用当前日线覆盖信号日 |
| 信号日以后的 OHLCV | `stock_sync.status='ok'` 的本地不复权行情 | 新数据或修订可改变成熟状态和结果 |
| 交易日历 | 优先 `calendar.db` 冻结指定读取区间；缺覆盖时用当前配置日历 | 当前读取窗口的日历，不保证等于生成报告时的日历 |

`LatestReviewDataDate` 取请求代码集合内成功不复权同步日期的最大值，作为 `data_as_of`。随后每只股票取不晚于该日期的最新成功窗口，缺失代码跳过。这个最大日期不表示每只股票都更新到了同一天。

后续行情批量读取处于一个只读事务中；报告、冻结输入、最大日期和日历是分步读取，整次投影没有一个覆盖所有来源的共同快照事务。日历不访问远端。缓存打开失败可落到配置日历；已打开缓存出现非“缺失/覆盖不足”的读取错误，则作为日历不可用处理。

### 3. 状态按实际分支确定

事件的 `state`、`state_reason`、`missing` 描述不同层面的事实。`missing` 不为空不一定意味着 `state=missing_data`，例如等待未来交易日也会填写 `future_sessions`。

| 条件 | 事件状态 | 原因或补充字段 |
| --- | --- | --- |
| 旧报告或冻结参数不支持 | `unsupported` | 保留具体参数错误或旧报告原因 |
| 没有该股冻结原始输入 | `unsupported` | `frozen_report_input_missing`；缺 `frozen_signal_bar` |
| 有冻结输入，但找不到信号日 | `missing_data` | `signal_bar_missing` |
| 没有当前本地行情 | `missing_data` | `current_market_history_missing` |
| 当前窗口没有信号日后的 bar | `pending` | `waiting_for_next_session` |
| 有未来 bar，但日历不可构造 | `missing_data` | `calendar_unavailable` |
| 模拟返回 error | `missing_data` | 通常 `simulation_failed`；保留缺失证据 |
| 已入场且有退出日 | `mature` | `target/stop/stop_gap/timeout` |
| 已入场但无退出日 | `pending` | `horizon_not_reached` |
| 尚未入场，模拟拒绝执行 | `not_entered` | `entry_skipped/cash_insufficient/risk_budget_insufficient` |
| 尚未入场，缺下个交易日 | `missing_data` | `missing_entry_session` |

已有入场分支优先于 `outcomeState` 的状态映射。因此，模拟器若发现退出日缺口并返回 `missing_exit_session`，当前事件仍为 `pending/horizon_not_reached`，`exit_reason` 留下 `missing_exit_session`。重建现状时应保留这个差异；若要统一归到缺数据，需要另行修改实现和回归测试。

`net_pct` 只在成熟事件上设置；未成熟事件可有 MFE/MAE，但没有最终净收益。未知数字使用指针与 `omitempty` 省略，不能替换成 0。日历不可用会附加日级 `calendar_unavailable`，事件还按自身读取情况分类。

### 4. 参考成交与 T+1/T+3/T+5

复盘调用 `strategy.Simulate`，使用冻结策略的 `MaxHoldingDays`。其入场条件包括下一交易日连续、成交量非零、开盘偏离未超限、日内振幅至少 0.005，以及预算和严格净亏损限制允许生成计划。入场价是开盘价加滑点并向上按分取整；超过当日最高价容差时不模拟成交。

卖出最早从买入后的下一交易日检查。日线不能恢复盘内先后关系：同日止盈与止损均触发时保守走止损并标记 `ambiguous`；开盘向下越过止损产生 `stop_gap`。一字跌停可继续等待，不能保证最长持有期限当天一定完成退出。费用、涨跌停规则和滑点均由成交模块处理，复盘不另写近似公式。

检查点相对**信号日**编号：T+1 是入场日收盘估值，T+3、T+5 是对应后续交易日收盘估值。它们扣除预留退出成本，但不表示 T+0 可以卖出。模拟提前退出后不补之后的检查点；未来数据不足时也不合成缺失检查点。默认持有期限取决于冻结报告，不能固定把 T+5 当作实际退出日。

`reference_plan` 是生成报告时的参考计划，`outcome` 则使用实际后续开盘假设重算；两者价格不完全相同是允许的。MFE/MAE 来自日线极值的模拟统计，不能视为可实现最优成交。

### 5. 聚合分母与证据编号

`aggregate` 包含 `all`、`recommended`、`observed` 三组。分组只看冻结候选的 `Recommended`；`DailyRecommended`、`EligibleRecommended`、观察排名和合格排名保留展示，但不重定义分组。观察组是推荐组的补集，并非另一个独立实验对照组。

```text
total = mature + pending + not_entered + missing + unsupported
entered = mature + pending 中 entry_date 非空的数量
mean_net_pct = 成熟事件净收益总和 / mature
positive_rate = 成熟事件中 net_pct > 0 的数量 / mature
```

`positive_rate` 是 0～1 的比例；`net_pct` 等收益字段以百分数数值表达。`mature=0` 时平均净收益和正收益比例省略；未入场、缺失、未成熟、不支持均不进入收益分母。

`target/stop/stop_gap/timeout`、`positive`、`loss_breach`、`ambiguous` 只统计成熟事件。`loss_breach` 使用 [BreachesLossLimit](../../internal/strategy/risk.go) 的严格亏损判定；最差 MAE 也仅取成熟事件。即使 pending 事件已有 MAE，也不进入 `worst_max_adverse_net_pct`。

单股详情的证据 ID 在事件内固定：

| ID | 内容 | 来源 |
| --- | --- | --- |
| E1 | 报告日期、目标日、修订、策略和 schema | 报告 |
| E2 | 候选名次、推荐、机会分、风险与理由 | 报告候选 |
| E3 | 冻结信号日 OHLCV | 冻结输入 |
| E4 | 模拟状态、入退场、收益、MFE/MAE | 成交模拟 |
| E5 | 检查点 | 成交模拟 |
| E6 | 结构门控 | 报告候选，成功进入模拟结果分支时附加 |
| E7 | 缺失项 | 复盘服务 |

AI 服务会重新裁剪和编号证据，不能跨请求用 E1/E2 作为永久数据库标识。

### 6. API、取消与网页降级

[handler.go](../../internal/dashboard/handler.go) 提供两个 GET/HEAD 接口：

```text
/api/review?as_of=YYYY-MM-DD[&revision=<64位修订>]
/api/review/event?as_of=YYYY-MM-DD&code=sz000001[&revision=<64位修订>]
```

重复参数、未知参数、非法日期/代码/revision 返回 400；未找到报告或事件返回 404；服务或存储不可用返回 503；截止时间返回 504。服务端请求超时为 15 秒，网页对应读取设为 16 秒。响应沿用 `no-store` 和安全头。

入口先检查 context，存储查询也传递 context。但逐事件循环与 `strategy.Simulate` 没有逐股/逐 bar 的取消检查；不能把 15 秒 HTTP 期限描述成所有纯计算都能立即中断的保证。

[review.js](../../internal/dashboard/static/review.js) 按日期、修订和代码更新 URL，切换时取消旧请求并用请求序号丢弃迟到结果。加载详情时先隐藏旧详情，失败显示重试。不同日期或修订加载失败会清除对应内容；同一上下文刷新可保留已有快照并显示错误，不应将其描述为新数据。

应用没有内置普通用户或管理员。公网只读模式允许复盘 GET/HEAD，屏蔽 AI 和配置交互；代理登录与 401/403 属于部署侧验收。不要以网页可打开代替身份验证。
