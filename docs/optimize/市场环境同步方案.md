# 市场环境同步方案

核对基线：`efdb2fb`，2026-10-29。本文说明核心指数、行业与概念板块的同步、独立存储及只读展示；验收命令作为复现入口，不表示本次已执行或线上已验证。

## S｜情境：复盘需要市场背景，但股票发布不能被板块上游拖垮

股票日线报告与指数、板块行情有不同的代码空间、历史范围和失败容忍度。市场环境模块从腾讯取核心指数，从东方财富发现板块并取日线，写入独立 `context.db`。日线采集期间可以并行运行；板块请求失败不会直接否决股票报告。

当前市场环境的直接消费方包括复盘页、`predictor-eval` 的市场分层评估，以及新增的 `market-signal` 指数方向信号。指数方向信号的模型、验证和影子输出见[指数方向信号](../market-signal.md)；本文只说明输入与采集边界。板块代码不进入 `leaders.yaml`、股票筛选或可交易股票集合。日内高低点模型中的市场/行业特征另有输入契约，不能因为存在同名“市场环境”就认定它们读取本库。

## T｜任务：让“同步结束”和“数据新鲜”分别可检查

| 边界 | 当前契约 |
| --- | --- |
| 核心指数 | 上证 `sh000001`、深证成指 `sz399001`、创业板 `sz399006`、沪深300 `sh000300`、科创50 `sh000688` |
| 板块集合 | 每轮发现东方财富行业与概念列表，按 `BK` 加四位数字识别；同代码可同时属于两类 |
| 行情截止 | CLI 限定已完成交易日；保存的数据日期不得超过 `as_of` |
| 隔离 | 独立数据库和同步状态；已进入同步的板块错误不改股票报告结果 |
| 持久化 | 每最多 20 个有效标的一批事务提交；成功批次在后续失败时保留 |
| 展示 | 每条记录保留实际最后日期，用 `stale` 表示落后；不把旧价格伪装成所选日价格 |
| 完成含义 | `SyncResult.status=complete` 表示本轮工作项无失败，不等于所有标的都有 `as_of` 当天 bar |

## A｜行动：发现、抓取、批量保存，再按日期投影

### 1. 入口与生命周期

`stock-watcher sync-context [-as-of YYYY-MM-DD]` 只同步市场环境。日期省略时取配置日历最近已完成交易日；显式日期必须是已完成交易日。禁用 `market_context` 时命令报错。命令输出 JSON；结果不是 `complete` 时返回非零退出码。

[主 CLI](../../cmd/stock-watcher/main.go)在打开 `market.db` 之前分派 `sync-context`，但已经通过 `storage.Open` 获取数据目录写锁，因此手工执行仍需停止持有同目录锁的 `run`。`ContextDB` 本身没有单独的应用级锁文件。

启用时，[runtime](../../runtime/runtime.go)初始化 `context.db`，注册 `Monitor.MarketContextSync` 包装回调；独立 `sync` 与 `once` 也注册该回调。回调先执行境内 `ForDate`，未返回错误时再依次采集恒生日线和韩国分钟；`sync-context` 使用相同的后续采集顺序。`once` 只有实际触发日线同步时才触发环境同步，不保证每次都采集。

[Monitor.Sync](../../internal/monitor/monitor.go)在日线流程中并发启动环境回调，返回前等待它结束。回调和日线共享整体 context、取消与同步期限。上游失败仅写日志及环境状态，不撤销股票成果；但等待仍会占用整个命令的完成时间。

恒生日线和韩国分钟采集失败只在未取消时写警告，不改境内 `SyncResult` 和 `context_sync`，因此境内 `complete` 不证明两个附加源成功；境内返回 partial 但无 error 时仍会尝试附加采集。当前包装回调也不会把附加采集阶段的取消重新作为返回错误传播。

独立库不意味着所有故障都被隔离：运行时启动阶段 `InitContext` 失败会返回初始化错误；CLI `sync/once` 打开环境运行时失败也会退出。隔离保证针对已经成功注册并启动的同步回调。

环境变量前缀是 `STOCK_WATCHER_CONTEXT_`，对应后缀为 `ENABLED`、`REQUEST_INTERVAL`、`WORKERS`、`HISTORY_LIMIT`、`EASTMONEY_LIST_ENDPOINT`、`EASTMONEY_KLINE_ENDPOINT`、`TENCENT_ENDPOINT`、`KOREA_ENDPOINT`、`HANG_SENG_ENDPOINT`、`KOREA_MINUTE_ENDPOINT`；不是 `MARKET_CONTEXT_*`。定义见 [配置校验](../../internal/config/marketcontext.go)和[环境覆盖](../../internal/config/environment.go)。

一般端点要求 HTTPS 或回环 HTTP，并禁止内嵌凭证、查询参数和 fragment。板块 K 线明确允许公开 `push2his.eastmoney.com` 的 `/api/qt/stock/kline/get` HTTP 路径；该例外不会放宽其他地址或路径。客户端禁用重定向，每个响应体最多 16 MiB。

当前数据目录默认 `data`、`require_cifs=false`；生产 CIFS 场景需显式设置 `STOCK_WATCHER_REQUIRE_CIFS=true`。模块使用公开行情，不要求专属 API Token，但仍经过全局配置加载与校验，不能跳过股池或其他已启用功能的配置错误。

### 3. 板块发现与数据校验

每轮先分页请求行业 `m:90+t:2`，再请求概念 `m:90+t:3`，每页 100 条。首响应 total 必须在 1～5000，分页次数另有限制。列表接受数组或索引对象，代码必须匹配 `^BK[0-9]{4}$`，名称不能为空。

同代码出现在两个列表时合并为 `category=industry,concept`；结果按代码排序。同一代码只抓取一次历史，展示汇总可分别计入行业和概念两类。任一发现请求失败，整轮在抓取指数与板块前退出，并尝试保存 `failed/discovery` 状态；不会退回旧板块列表。

发现流程不删除本库中本轮未再出现的板块，也没有历史成员映射。列表提前返回空页会结束该类分页，当前没有对发现条数与 total 做最终一致性断言。因此“发现全量”表达的是逐页遍历意图，不能当作供应商完整性保证。

指数请求固定最近四个自然年的起点、640 根和 `qfq` 参数，优先解析 `qfqday`，缺失时用 `day`，不会为指数做长期分页补齐。板块请求使用 `secid=90.<代码>`、日线 `klt=101`、不复权 `fqt=0`。

解析后检查代码、日期递增、有限非负数值和 OHLC 范围；未来日期过滤，重复/倒序日期拒绝。板块响应还核对 `market=90`，返回行数不得超过请求上限加一。短于要求字段数的板块行会跳过；这与数值或 OHLC 错误导致拒绝不同。

### 4. 增量范围与写入

同步先读所有标的 `MAX(trade_date)`。已有最后日期不早于 `as_of` 的标的记作 `skipped`，同时计入 `succeeded`，本轮不再请求它的行情。板块发现仍每轮执行。

| 情况 | 请求和写入行为 |
| --- | --- |
| 新板块 | `beg=0`，取最多 `history_limit` 根；没有历史即失败 |
| 已有板块落后 | 从上次最后日期前 3 个自然日重取重叠尾部；同日期 upsert 修订 |
| 指数落后 | 重新取固定 640 根窗口，未使用板块的增量起点 |
| 已有板块返回空历史 | 允许仅更新元信息；旧价格保留，该次可计为成功 |
| 已到目标日期 | 跳过抓取；不会重取当日修订或更新该标的名称/分类 |

最多 20 个快照通过 `SaveInstruments` 一次提交。批次失败时该批全部计入失败，之前成功批次不回滚；下一批仍可继续尝试。这不是整轮原子事务。

`context.db` 仍为 schema 1，当前建库语句包含八张表：

| 表 | 用途 |
| --- | --- |
| `context_instrument` | 境内指数/板块代码、名称、分类、来源 |
| `context_bar` | 境内日线；代码+交易日主键，REAL 价格、原始成交量和金额 |
| `context_sync` | `id=1` 的最近境内同步状态，无逐次历史或冻结 revision |
| `context_minute` | 境内指数原生 5 分钟缓存 |
| `context_minute_30` | 境内指数原生 30 分钟缓存，与 5 分钟分表保存 |
| `context_korea` | KOSPI/KOSDAQ 日线 |
| `context_hang_seng` | `hkHSI` 恒生日线，供下午影子模型使用 |
| `context_korea_minute` | KOSPI/KOSDAQ 分钟前向缓存，当前不进入模型 |

新增表通过可写打开时的 `CREATE TABLE IF NOT EXISTS` 补齐，没有提升 `user_version`。只读兼容入口对缺失的分钟、韩国和恒生表返回空缓存，旧 schema 1 库仍可提供境内日线；不能因 schema 号相同就假设八表均存在。

写连接使用 `DELETE` journal、`FULL` 同步、外键、5 秒 busy timeout、单连接；只读连接为 `query_only=ON`。数据根必须存在且符合挂载要求，库文件不得为符号链接；只接受 schema 1。写批次前重新检查数据根，失败后不切换本地路径。

### 5. 错误、超时和取消

请求层最多尝试 3 次。网络错误、响应体读取失败、HTTP 429 和 5xx 可重试，间隔依次为 200ms、400ms，且每次仍经过共享节流器。其他非 200 状态直接失败，解析错误和超大响应不会进入另一来源重试。

单个标的失败增加 `failed`，保留至多 40 个错误样例，每条原因最多保留 240 个字符。其余标的继续。最终状态按以下规则确定：

```text
succeeded == 0                 -> failed
succeeded > 0 && failed > 0    -> partial
otherwise                     -> complete
```

`skipped` 已包含在 `succeeded`。调用者取消时返回 `ctx.Err()`，结果标为 `partial`，并尝试用后台 context 写 `error_kind=canceled`；未完成工作项不必全部计入 `failed`，因此取消结果不能仅靠三个计数求和判断完整性。

状态持久化也有边界：开始写 `running`、发现失败及取消时的状态写入属于尽力而为；读取最后日期异常可能留下 `running`，正常结束时最后一次状态写入失败则返回错误。详细 `SyncResult.Errors` 留在命令结果中，不存入 `context_sync`，API 的 `sync_errors` 字段当前不会自动从这些样例恢复。

### 6. 指数分钟与海外输入

新增命令写入上述独立缓存，不能与股票 `backfill-minutes` 混用：

| 入口 | 当前行为 |
| --- | --- |
| `sync-index-minutes [-as-of D] [-from D]` | 新浪顺序抓取上证指数、创业板指各自原生 5/30 分钟；默认向前三年，每个缓存独立事务 upsert |
| `sync-korea-context [-as-of D] [-from D]` | Naver KOSPI/KOSDAQ 日线补采；不随常规 `ForDate` 自动执行 |
| `sync-hang-seng-context [-as-of D]` | 腾讯恒生日线，另随环境同步自动执行 |
| `sync-korea-minutes [-as-of D]` | 请求韩国时区截止日前七天至截止日 16:00 的近期分钟，另随环境同步自动执行 |

[指数分钟命令](../../cmd/stock-watcher/index_minutes.go)补建缺少的指数元信息，用每股 48 根与每股 8 根分别统计完整 5/30 分钟日；`status=ok` 不保证请求的三年区间全部覆盖。新浪来源窗口有限，30 分钟也直接采原生序列，不由短期 5 分钟缓存扩造。5 分钟写入后，30 分钟请求失败不会回滚前一事务。

这些新增手工采集命令在主 CLI 的 `storage.Open` 之前分派，直接 `InitContext`，当前没有获取数据目录主写锁。运行时自动采集受常驻进程生命周期管理；手工操作应避免并发写入，不能沿用 `sync-context` 的写锁保证。详见[影子源实现](../../internal/marketcontext/shadow.go)。

恒生日线最多约 640 根；韩国分钟前向窗口受 Naver 可返回历史限制，请求七天不等于七天可用数据。韩国分钟当前仅保存证据，模型入口不读取该表；它与可进入会话模型的韩国日线不同。海外缓存不进入境内 instrument 列表和涨跌汇总，也没有独立持久化同步成功状态。

### 7. API、快照与消费

`GET/HEAD /api/market-context[?as_of=YYYY-MM-DD]` 只读本库。参数省略时使用最近同步状态的日期；显式日期只校验格式，不重复 CLI 的“已完成交易日”检查。未知参数、重复日期或非法日期返回 400；其他方法返回 405。

处理器预算为 20 秒，每个标的读取截止所选日最近 21 根。数据库/同步状态未建立返回 404；存储不可用或查询错误返回 503。API 不触发同步，也不会为了显示缺失日期向上游抓行情。

快照 schema 1 包含总体状态、最近同步时间、指数/板块列表、分类/涨跌汇总及警告。`BuildSnapshot` 按所选日投影：

- `as_of` 为实际最后 bar 日期，落后所选日则 `stale=true`；完全没有可用 bar 的标的不出现在列表。
- `change_pct` 使用最后两个可用收盘价；少于两根时保持零，不能理解为已证实平盘。
- MA5/MA20 样本不足时为零，趋势为 `unknown`；严格 `close > MA5 > MA20` 为 `up`，反向为 `down`，其他为 `mixed`。
- `complete` 只统计实际日期等于目标且非 stale 的记录；`total` 包含库中全部 instrument，两者可不同。
- 陈旧板块不进入上涨/下跌/平盘计数；行业/概念计数仍按分类记录，双分类可重复计数。

同步状态属于最近一轮；选历史日期时仍读取该状态，日期不一致会给警告。不能把历史行情投影称为当日冻结快照，也不能把 `status=complete` 当作 `complete=total` 的替代。

[复盘页脚本](../../internal/dashboard/static/market-context.js)显示五个指数卡片、行业/概念数量、搜索/类型筛选/排序和分批显示的板块列表；切换日期先取消旧请求，避免旧响应覆盖新日期。无数据和请求失败显示独立空态。

[predictor-eval](../../cmd/stock-watcher/predictor_eval.go)最多读取 120 根沪深300日线，构造市场状态分层；库缺失、读取失败或无沪深300时返回“市场数据不可用”，不补网络请求。它使用当前库内历史，市场环境数据自身没有不可变快照保证。

新增 `GET/HEAD /api/market-signal[?as_of=D]` 与只读 CLI `market-signal [-as-of D]` 读取本库计算上证/创业板下一交易日及上午/下午方向，不触发下载或持久化模型。缺省日期来自 `context_sync.as_of`；显式日期允许直接按截止日读取。API 参数错误为 400、缺库或缺省日期状态缺失为 404、存储读取失败为 503、计算失败为 500，其他方法 405。

[处理器](../../internal/dashboard/market_signal.go)读取境内日线、5/30 分钟、韩国日线与恒生日线；会话模型优先用原生 30 分钟，缺该缓存时回退 5 分钟。韩国日线可追加正式会话特征，恒生只进入下午影子字段，韩国分钟不读取。陈旧/缺历史等业务状态随 JSON 返回，不能以 HTTP 200 当作信号可用。复盘页新增方向卡片、会话与影子指标，具体字段、截断及统计限制以[指数方向信号](../market-signal.md)为专题入口。
