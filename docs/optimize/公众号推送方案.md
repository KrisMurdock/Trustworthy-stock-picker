# 公众号推送方案

核对基线：`3e2510b`，2026-10-29。当前实现是微信公众号“草稿”通道，成功只代表草稿已写入草稿箱。

## S｜情境：文章需要人工确认

[internal/wechat](../../internal/wechat) 把精排解读和盘前区间研究转换成公众号文章。通道没有发布、群发或删除线上文章的方法；人工仍需在公众号后台审核并发布。文章生成在 [notify/report](../../internal/notify/report) 和 [dayrange/premarket_article.go](../../internal/dayrange/premarket_article.go) 完成，纯函数不访问行情和微信接口。

同一投递账本可能同时承载飞书、公众号和其他路由。公众号事件使用独立通道名（生产配置为 `wechat-draft`），不能把通道送达解释成文章公开发布。

## T｜任务：安全地创建一篇可审核草稿

| 约束 | 当前行为 |
| --- | --- |
| 凭证 | AppID、AppSecret、作者名由配置加载；敏感值只在内存/请求中使用，不写日志和错误文本 |
| 文章 | 标题必填且最多 32 个 Unicode 字符；作者最多 16；摘要最多 120；正文不能为空 |
| HTML | 渲染后少于 20,000 个 Unicode 字符且少于 1 MiB；超限在本地拒绝 |
| 语法 | 受限 Markdown：标题、段落、列表、引用、有限卡片和 `[[chart:id]]`；不允许脚本、class、外部 CSS 或任意链接 |
| 图片 | 图表先生成 PNG，再上传到微信素材接口；占位符必须全部解析，否则不创建草稿 |
| 网络 | 禁止 HTTP 重定向；响应体上限 64 KiB；客户端默认请求超时 10 秒 |
| 认证 | access token 过期前 5 分钟刷新；微信返回无效凭证时最多刷新一次并重试一次 |
| 结果 | `/cgi-bin/draft/add` 返回 `media_id` 才算成功；不调用发布/群发接口 |
| 不确定 | 请求取消或超时发生在服务端确认之后时，记录 `unknown`，不自动盲重试，避免重复草稿 |

## A｜行动：生成、校验、上传、建稿

### 1. 文章路由

当前文章来源分为两条：

- `second_stage`：精排候选、分层证据、风险边界和图表；
- `wechat_premarket`：下一交易日的盘前高低点区间、验证状态和研究限制。

路由和账本事件由 [monitor/startup.go](../../internal/monitor/startup.go) 及通知报告转换层组装。文章正文保留研究语境和免责声明，不把历史命中率、区间或候选分数写成成功概率、收益承诺或买卖指令。

### 2. HTML 渲染子集

[html.go](../../internal/wechat/html.go) 将换行规范化后逐行解析：

- `#`～`####` 标题、段落、无序/有序列表、引用；
- `:::card [neutral|blue|green|amber|grey]` 卡片块，卡片内仅允许三级和四级标题及普通内容；
- `[[chart:<id>]]` 图表占位符；ID 必须匹配小写字母、数字和短横线；
- 图片 URL 只能是带主机的 `http` 或 `https`，并转义属性内容。

未知 Markdown 行会按普通段落处理；这意味着“未知语法一律拒绝”不是当前契约，调用方如需严格格式必须在生成文章前校验。脚本标签不会作为 HTML 执行，而会被转义为文本；任意外链写在普通文本中同样不会生成链接。带图表的正文若缺少对应上传结果会失败关闭。

### 3. 微信请求顺序

`Client.Send` 的顺序是：

```text
校验文章 → 生成并上传图表 → 渲染 HTML → 获取封面素材 ID → 调用 draft/add
```

封面优先使用配置的 `thumb_media_id`，否则上传内置 `cover.png`。图表 PNG 按内容哈希在进程内缓存 URL；封面 ID 也在进程内缓存。缓存丢失或进程重启不代表微信草稿已不存在，不能用本地缓存当作远端状态。

请求使用 `access_token` 查询参数。响应体超过 64 KiB、JSON 损坏、HTTP 错误、业务 `errcode` 或缺少 `media_id` 都转换成投递错误；错误消息只保留分类和状态码，不能包含 token、AppSecret 或响应正文。

### 4. 错误分类和账本

业务错误根据微信错误码映射为永久或可重试错误；例如无权限/白名单错误是永久错误，限流通常可重试。网络错误和 5xx 可由通用投递账本退避，取消/截止时间不代表服务端没有创建草稿，因此保留 `unknown`。`retry` 只解锁账本终态，不会检查公众号后台是否已存在同内容草稿。

账本按事件日期、事件类型和通道去重。已有 `pending`、`in_flight`、`delivered` 或 `blocked` 记录时，不再新建同一事件；`unknown` 需要明确的人工/运维重试路径。这里的幂等是本地事件幂等，不是微信公众号草稿箱的全局内容幂等。

## 重建规格

```text
BuildArticle(report_or_forecast) -> notify.Article{title,digest,body,charts}
RenderHTMLWithImages(body, uploaded_images) -> html
DraftClient{Name, Send, Close}
Ledger.Enqueue(as_of, event, channel) -> created_or_existing
```

`DraftClient` 公开接口只有 `Name`、`Send` 和 `Close`。实现不应预留生产可调用的 publish、mass-send 或 delete 方法。`Send` 不直接处理账本；它只负责一次文章投递，并返回可分类的错误。
