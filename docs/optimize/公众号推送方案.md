# 公众号推送方案

核对基线：`33ab655`，2026-10-29。当前实现是微信公众号草稿通道；成功表示接口确认创建草稿，文章仍需在公众号后台人工审核和发布。

## S｜情境：精排与盘前研究需要人工审核

[internal/wechat](../../internal/wechat) 把结构化文章转换成微信 HTML，上传图片并创建草稿。客户端没有发布、群发或删除文章的方法。`Send` 只返回 `error`，不会把草稿 ID 返回给调用方或写入投递账本。

精排正文由 [notify/report](../../internal/notify/report) 生成，盘前文章由 [dayrange/premarket_article.go](../../internal/dayrange/premarket_article.go) 汇总预测和报告后交给转换层生成。转换函数不自行请求行情或微信；上层负责取得输入与持久化消息。

生产通道名为 `wechat-draft`，同时订阅 `second_stage,wechat_premarket`。两类文章走不同账本与发送执行器，错误恢复行为也有差异。

## T｜任务：生成可审核的研究草稿

| 约束 | 当前行为 |
| --- | --- |
| 启用条件 | AppID、AppSecret 必填，且精排或日内区间至少一条推送链路启用 |
| 作者 | 可为空；非空最多 16 个 Unicode 字符 |
| 文章 | 标题必填且最多 32 字，摘要最多 120 字，正文不能为空 |
| HTML 大小 | 渲染结果严格小于 20,000 字且小于 1 MiB，等于上限也拒绝 |
| 语法 | 标题、段落、列表、引用、粗体、有限卡片和图表占位符 |
| 普通 HTML 文本 | 转义后显示，不直接解释成脚本、标签或任意链接 |
| 网络 | 禁止跟随重定向；响应体上限 64 KiB；客户端缺省请求超时 10 秒 |
| token | 进程内缓存；正常提前 5 分钟刷新，短 TTL 另有下限处理 |
| 成功依据 | `draft/add` 返回非空 `media_id`，`Send` 返回 `nil` |
| 重复风险 | HTTP 确认丢失或账本保存失败后可能重发，远端没有内容查重 |

凭证由 [config.go](../../internal/config/config.go) 的私有文件与环境变量加载。配置校验负责拒绝缺失凭证，`NewDraftClient` 本身不重复完成整套业务配置校验。标题、摘要和作者会规整为单行，正文去掉首尾空白后再校验。

## A｜行动：路由、渲染、上传与入账

### 1. 两类文章的路由

| 路由 | 输入与调度 | 账本 |
| --- | --- | --- |
| `second_stage` | 精排候选、证据、风险与图表；主 monitor 在报告入队时处理 | `state/delivery.json` |
| `wechat_premarket` | 目标交易日的冻结区间预测、已有精排与执行状态；dayrange 发布盘前结果时处理 | `state/dayrange-delivery.json` |

盘前文章来源于已保存预测，按目标日筛选；没有预测或没有匹配文章通道时不建稿。文章的“观察”“候选”等状态取决于报告与研究证据，不代表交易订单。草稿保留研究限制，不把模型区间、历史命中率或候选分数描述成收益承诺。

主报告入队在同一数据日、同一通道已有记录时不重建该通道消息，检查不区分事件类型。盘前文章则使用 `dayrange:premarket-article:<目标日>` 作为稳定事件 ID；同 ID 再入队保留原正文和状态。

两条链路不共享一个跨账本去重键。同名 `wechat-draft` 同时存在于两份账本不代表重复事件，分别表示不同文章任务。

### 2. HTML 渲染子集

[html.go](../../internal/wechat/html.go) 统一换行后逐行解析。支持 `#`～`####` 标题、段落、无序/有序列表、引用与 `**粗体**`。未知 Markdown 行按普通段落输出；普通外链写成文本也不会自动成为 `<a>`。

卡片使用 `:::card <tone>` 与 `:::` 围栏。色调包括 `neutral/blue/green/amber/grey`，也接受 `gray`；未知色调回退 neutral。卡片内标题只能用三级或四级，空卡片、嵌套、未闭合围栏和孤立结束符会报错。

图表占位符必须独占一行，形式为 `[[chart:<id>]]`。有效 ID 长度 1～64，首字符为小写字母或数字，后续可含短横线；匹配到的占位符若没有上传结果就失败。不匹配语法的普通文本不因此自动触发“缺图”错误。

图片 URL 只接受带主机、无内嵌用户信息的 `http/https`，属性和图注都转义。当前校验没有微信 CDN 主机白名单，不能把“通常来自微信上传响应”写成“只允许微信域名”。

输出使用固定 inline style，不透传用户的 class、外部 CSS、脚本或任意 HTML 属性。`<script>` 等普通输入会变成可见转义文本；它们不是统一在入口被拒绝。

### 3. 创建草稿的请求顺序

`Client.Send` 先检查 context，随后按下列顺序执行：

```text
校验文章 → 生成/上传图表 → 渲染 HTML 并检查大小
        → 取得封面素材 → 获取 token（按需） → draft/add
```

图表上传也需要 token；因此 token 请求可能在图表或封面阶段发生，不能要求它固定为建稿前的唯一首请求。正文渲染失败会停止建稿，但此时图表素材可能已经上传，当前没有清理已上传素材的补偿流程。

| 用途 | HTTP 接口 |
| --- | --- |
| 获取稳定 token | `POST /cgi-bin/stable_token` |
| 正文图片 | `POST /cgi-bin/media/uploadimg` |
| 缺省封面永久素材 | `POST /cgi-bin/material/add_material?type=image` |
| 创建单篇草稿 | `POST /cgi-bin/draft/add` |

封面优先使用配置的 `thumb_media_id`，未配置时上传内置 `cover.png`。请求中的文章类型为 `news`，评论相关开关为关闭。微信返回 `media_id` 后，内部 `addDraft` 返回该字符串，外层 `Send` 丢弃它，仅将成功/错误交给通用通道接口。

图表按 PNG 内容 SHA-256 缓存上传 URL，缓存达到 128 项后在存入新项前清空；封面 ID 也只在进程内缓存。重启后素材可能再次上传。本地缓存既不是草稿档案，也不能查询后台是否已有同内容文章。

### 4. token 与短 TTL

正常 token 有效期按 `expires_in - 5分钟` 缓存；若结果不足 1 分钟，改用 `expires_in/2`，仍不足 1 分钟则至少缓存 1 分钟。不能把所有 TTL 都写成严格提前 5 分钟刷新。

图片上传、封面上传和建稿各自最多尝试两次：第一次遇到 `40001/42001` 清缓存后再取得 token，随后重试当前操作一次。这里的重试次数按操作计算，不是整篇文章总共只有一次 HTTP 重试。

业务 `errmsg` 和响应正文不进入投递错误文本。对外错误保留固定原因、业务码和 HTTP 状态，token 与 AppSecret 只参与请求。缺少成功字段也按错误返回，不将 HTTP 200 本身视为完成。

### 5. 错误分类与取消边界

[wechat.go](../../internal/wechat/wechat.go) 的传输分类如下：

| 情况 | 客户端返回 |
| --- | --- |
| 文章校验、图表渲染、HTML 渲染失败或正文超大 | `DeliveryError{Kind:permanent}` |
| HTTP 请求失败且请求 context 已取消/截止 | 原 context 错误 |
| HTTP 客户端超时/网络错误，但父请求 context 尚有效 | `retryable`，原因 `wechat_network` |
| 响应读取失败、超过 64 KiB、JSON 解码失败、缺 token/素材 ID/图片 URL | `unknown` 类别 |
| HTTP 429 或 5xx | `retryable`，解析 `Retry-After` |
| 其他非 200，包括 3xx、401、403 | `permanent` |
| 微信业务 `errcode` | 包装为 `apiError`，内部携带 `DeliveryError` |

业务码 `-1/40001/42001/45009/45011/45066/89504/89505/268488001` 当前归为可重试；其他业务码默认永久。`45011/45066` 提供 1 分钟建议等待，`89504/89505` 为 5 分钟，最终仍与账本指数退避取较长值。

错误类别 `unknown` 不等于账本状态一定是 `unknown`。主 monitor 对普通返回错误调用 `MarkFailure`，未知类别进入 `pending` 并退避；只有发送返回错误且 context 取消/截止，或恢复遗留 `in_flight`，才走可能重复处理。

主 monitor 发送 context 受消息剩余有效期约束。发送返回错误时，父 context 取消保留 `unknown`；若只是消息到期则过期。发送返回 nil 则先保存 `delivered`，不因随后发现取消而改为未知。HTTP 客户端自己的 10 秒超时未必使该 context 截止，通常按可重试网络错误处理。

盘前文章的 dayrange 执行器另设最多 10 秒的发送 context；错误一般回到 `pending` 退避。它只直接断言 `*notify.DeliveryError`，不会解包 `apiError`，所以微信永久业务码在这条链路中当前可能被归为 `send_failed` 重试。主 monitor 使用 `errors.As`，可以识别该包装。不能将两个消费者的行为写成完全一致。

### 6. 重试、过期与重复草稿

通用 `Ledger.Due` 会自动选择未过期、已到重试时间的 `pending` 和 `unknown`。遗留 `in_flight` 恢复成 `unknown` 后也会再次进入发送候选，`PossiblyDuplicate` 仅记录风险，不阻止重发。

`retry [channel]` 只解锁主账本中未过期的 `blocked`，不检查微信后台，不处理已送达记录，也不操作盘前文章所在的 dayrange 账本。完整状态机见[通知调度与投递账本方案](通知调度与投递账本方案.md)。

远端建稿与本地保存成功状态之间没有事务。如果建稿成功但确认丢失，或者保存 `delivered` 时共享盘故障，重试可能新增相同内容草稿。需要人工在后台核对；当前没有媒体 ID 持久化、草稿列表查重或自动删除接口。

## 重建规格

```text
BuildArticle(report_or_forecast) -> notify.Article{Title,Digest,Body,Charts}
RenderHTMLWithImages(body, uploaded_images) -> (html, error)
Client.Name() -> string
Client.Send(context.Context, notify.Message) -> error
Client.Close()
Ledger.EnqueuePart(as_of, message, channels, part, sequence, dependency) -> error
```

实现必须保留“草稿成功”和“文章发布”的区别、文本转义、图表缺失拒绝建稿、凭证脱敏，以及持久化发送前后状态。若将来增加媒体 ID 持久化或统一执行器错误解包，应分别变更接口/账本契约和回归测试，不能仅修改文档宣布已经具备。

本篇没有使用真实公众号凭证或访问生产草稿箱。真实账号权限、IP 白名单、素材配额、草稿内容与后台人工发布效果仍需部署后验证；应用登录身份不参与微信服务端授权，二者应分开验收。
