# 策略实验档案

每次运行的固定指标卡片与 JSON 导出见[实验结果快照](experiment-result-snapshots.md)。

实验室把「假设 → 对照结果 → 缺点证据 → 下一步问题」保存为可追溯的父子记录。首版提供本地实验命令和只读网页，用现有机会评分建立基线，并验证上影线过滤和历史风险证据过滤。它支持预先定义的次日触达对照规则，不运行无界参数搜索，也不把实验结论直接用于日常推荐。

日线底部信号的描述性统计见[底部信号重复次数与反弹报告](bottom-signals.md)。独立工具 `cmd/bottom-study` 读取冻结快照，输出新触发次数、反弹等待时间和先跌风险；该研究不模拟分批成交，也不写入网页的交易回测档案。

## 创建与复现

使用部署时相同的配置和已挂载数据目录：

```bash
# 默认采用最新已保存行情日期；也可追加 -as-of YYYY-MM-DD
./bin/stock-watcher experiment -policy baseline

# 用上一条命令最终 JSON 中的完整 id 建立对照
./bin/stock-watcher experiment -parent <完整ID> -policy upper-wick

# 只选当时已完成的历史证据通过亏损与推荐门槛的候选
./bin/stock-watcher experiment -parent <新基线完整ID> -policy risk-qualified

# 在同一固定快照上重跑基线，仍生成新记录
./bin/stock-watcher experiment -parent <基线完整ID> -policy baseline

# 开发实验完成后，消耗父记录预留的保留区间；不能与 -from/-through 同用
./bin/stock-watcher experiment -parent <基线完整ID> -holdout
```

`upper-wick` 和 `risk-qualified` 要求父实验。子实验从父档案恢复股池、日历、参数、前复权特征日线和不复权模拟日线，即使后续行情同步或当前配置变化也沿用原输入。子实验的 `-as-of` 若与父快照不同会拒绝运行。代码升级后可以重跑，但版本不同不会显示数值改善结论；应先在新版本建立基线，再建立对照。代码版本由 `make build` 写入，复现实验应保留对应提交或镜像。

命令不请求日线行情、不创建通知客户端、不发送消息。它只读 `market.db`；新快照缺少覆盖预热到退出窗口的交易日历时，会优先读取 `calendar.db` 缓存，必要时请求 BaoStock/Tushare 交易日历并写回缓存。实验独立取得 `.experiments.lock`，可与行情监控进程并行运行；一次只允许运行一个实验。最长运行 10 分钟。取消或失败会尽量在另一个 5 秒时限内保存状态；进程强制退出后，下一次实验命令取得锁时会将遗留运行标为「中断」。修改终态记录被拒绝。

## 选择回测区间

固定程序入口是 `stock-watcher experiment`：加载本地快照 → 按信号日已知特征选股 → 模拟入场和退出 → 计算指标 → 归档规则、结果、缺点证据和后续方向。网页的日期选择器生成可复制命令；网页仍是只读看板，不会直接启动任务。

```bash
# 区间为包含两端的信号日期，不是成交日期
./bin/stock-watcher experiment -policy conditional-entry \
  -as-of 2026-10-15 -from 2026-09-18 -through 2026-10-08
# 同一快照、相同区间和规则重算；不再依赖当前行情库
./bin/stock-watcher experiment -parent <本轮完整ID> -policy conditional-entry
```

`-from` 和 `-through` 必须一起提供，支持所有实验 policy。程序保留区间前的指标预热和已成熟历史证据，只统计所选信号日；交易日历必须覆盖区间，快照截止日必须足够覆盖最后一个信号日之后的买入和完整卖出期限。股票本身缺失的入场路径和退出数据仍会保留为未知/未决，不当成安全跳过。区间外没有有效信号时显示空样本，不伪造成功率。

子实验未指定日期时继承父区间，指定时覆盖父区间；更换区间后不显示相对父实验的改善量。显式选取的区间属于开发回测，**不声明独立留出区间**。不指定日期时，原日线实验保留原开发/留出划分，条件入场实验保留最后3个完整分钟交易日，并剔除卖出日触碰边界的样本。已经查看过结果的日期不能再次声称是独立验证数据。

`-holdout` 只消费父开发记录预留的区间，创建独立子记录，父记录保持不变。同一快照首次消费标为未污染；再次消费仍会归档，但标记为 `contaminated`，不得再声称独立样本外验证。旧快照没有冻结交易日历时拒绝消费，需要重新建立开发实验。

## 条件入场与买入日浮盈

`conditional-entry` 先使用固定机会排序确定下一交易日的 Top N，再按以下预先固定的入场规则回放5分钟行情：

1. 买入价区间是信号日不复权收盘价下方0.5%～2%，按分位取整；不是事后挑出的最低价。
2. 已结束5分钟线收盘在区间内，且相对当时已观察的日内低点反弹至少0.3%；下一根5分钟线开盘加滑点仍在区间且有成交量才模拟买入，最迟14:30。午休前信号不带入下午。
3. 入场前5分钟收盘跌破区间下沿，或首次反弹触发后开盘价跳出区间，放弃该股票。未触发不按未来收益补选其他股票。
4. 买入日收盘扣买入费用、预留卖出税费和滑点后的浮盈必须为正；它是事后验收指标，不用于提前排除亏损买入，也不代表当天实际卖出。
5. 下一交易日按5分钟线保守模拟止损、止盈或到期收盘退出。只计退出前已确认的最高价净触达2.5%／3%；同根5分钟线内顺序仍可能未知。分别统计次日触达率，以及“买入日为正且次日触达”的联合成功率，分母是全部实际入场，含未决。

新快照额外冻结不复权5分钟数据，并纳入摘要校验。旧日线快照不含分钟数据时拒绝运行此 policy，应不带 `-parent` 建立新根实验。当前分钟存储只覆盖较短窗口，不能用十年日线虚构十年盘中路径。固定规则试验不做参数搜索，也不自动发布次日买入推荐。

验收保留单笔净亏损严格小于3%的优先约束；存在买入日浮盈不为正的样本判定“买入日未达标”，入场分钟缺失不能判定通过。满足风险、买入日、完整证据、至少30个完整信号日与30笔完成交易后，再检查两档联合成功率是否达到80%。这些是历史试验门槛，不能保证未来买入日收盘、实际成交或亏损上限。

## RSI、MACD 与布林线对照

原机会评分已经包含 RSI 和 MACD。本轮在相同条件低吸成交规则上增加明确的信号日过滤，新增布林线位置与前一日变化证据；不改变日常看板排序或自动发布买入推荐。

| policy | 信号日筛选条件 |
| --- | --- |
| `conditional-entry` | 原机会排序，无额外过滤 |
| `conditional-rsi` | Wilder RSI14 为40～65且高于前一交易日 |
| `conditional-macd` | DIF > DEA，且2×(DIF−DEA)高于前一交易日 |
| `conditional-bollinger` | 布林 %B 为0.1～0.6且高于前一交易日 |
| `conditional-confluence` | 上述三个指标条件至少满足两项 |
| `conditional-all-three` | 上述三个指标条件全部满足 |
| `conditional-guard` | ATR14 ≤3%，距MA20在−5%～5%，量比0.8～2.5 |
| `conditional-confluence-guard` | 至少两项指标满足，并通过波动量能约束 |
| `conditional-chan-5-15-30` | 30m 中枢下沿/最近完成笔、15m 与 5m 底分型收复共同确认；缺失保持未知 |

MACD沿用EMA12/26、DEA为DIF的EMA9，初值使用对应窗口SMA；柱值为2×(DIF−DEA)。布林线使用20日收盘SMA±2倍总体标准差，%B=(收盘−下轨)/(上轨−下轨)，带宽=(上轨−下轨)/中轨；零带宽的%B记为未定义，不产生修复信号。前一日指标只计算到前一交易日。全部特征使用信号时可见的前复权窗口，成交价格继续使用不复权数据。

先过滤再按原机会分数和代码取Top N；只有信号日条件能决定入选，次日不触发不补位。原Top N被过滤的记录保存指标和过滤状态，不计算假设成交收益；前端同时显示全部候选、指标通过、预先入选和原Top N过滤数量，避免把空仓或样本减少说成盈利改善。

```bash
# 用已有分钟快照重跑新版本基线；代码/引擎改变时建立新的根基线并保留旧父档案
./bin/stock-watcher experiment \
  -parent <含分钟数据的旧实验ID> -policy conditional-entry

# 用新基线ID运行一组固定对照，自动继承信号区间
./bin/stock-watcher experiment \
  -parent <本轮新基线ID> -policy conditional-confluence-guard
```

七个指标对照要求父实验。页面支持选择这些规则并生成命令；没有分钟快照时提示先创建条件低吸基线。查看样本可读出RSI及MACD柱的昨日/今日值、DIF/DEA、布林上下中轨/%B/带宽及ATR/量比。旧记录没有这些值时明确显示未记录，不从同步后的行情补造证据。

这些门槛是实验假设，不是从指标定义推出的胜率。[Fidelity RSI说明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI)与[MACD说明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/macd)用于核对口径；[John Bollinger的规则说明](https://www.bollingerbands.com/bollinger-band-rules)也强调触及轨道本身不是买卖信号，相关指标叠加不能当作独立证据。参数在本轮结果前固定，所有组使用相同快照、区间、成本及成交方式，全部保留结果，不把最佳小样本比例解释成未来成功率。

缠论结构对照使用同一条件低吸成交路径，只增加固定 5/15/30 分钟结构过滤；该轮开发记录仅保留在本地研究目录，不随仓库发布。

## 次日触达目标

当前优先研究两个目标：**买入后的第 1 个可卖出交易日，最高价净盈利触达 2.5%／3%，两档成功率分别争取 ≥80%；单笔净亏损严格低于投入的 3%**。第 1 天指买入后的第二个交易日，不使用 `holding_days < 1`；日线没有精确成交时刻，不能据此声称持仓小于 24 小时。

```bash
# 新快照下建立次日基线
./bin/stock-watcher experiment -policy next-day-baseline
# 或加 -parent <旧实验ID> 复用原快照，建立独立的次日根基线
./bin/stock-watcher experiment -parent <旧实验ID> -policy next-day-baseline
# 用新的次日基线ID做预先定义的对照
./bin/stock-watcher experiment -parent <次日基线ID> -policy next-day-low-volatility
```

所有 `next-day-*` 实验都在首个可卖出日止损、止盈或到期收盘退出；无法卖出及除权仍保留未决。目标触达按最高价扣费/滑点计算，实际成交按原模型另外计算。只计退出前已确认触达；开盘已退出的后续反弹不算成功，同日触达/止损顺序不明不算成功。

| policy 后缀 | 固定过滤条件（只用信号日特征） |
| --- | --- |
| `baseline` | 原机会排序，不加过滤 |
| `upper-wick` | 上影线占当日振幅 ≤30% |
| `low-volatility` | ATR14 占收盘价 ≤2% |
| `pullback` | MA20 上行；距 MA20 -1%～3%；当日上涨；收盘位置 ≥60%；量比 ≤1.5 |
| `breakout` | 距前20日最高价 -0.5%～3%；量比 ≥1.2；收盘位置 ≥65%；上影线 ≤30%；MA20 上行 |
| `momentum` | MA5 > MA10 > MA20；5日涨幅 >0% 且 ≤10%；强于股池；RSI14 为50～75 |
| `volume-recovery` | 量比1.2～2.5；当日涨幅0%～4%；收盘位置 ≥70%；距MA20 -2%～8% |
| `balanced` | ATR14 ≤3%；上影线 ≤30%；MA20 上行；5日涨幅 ≤10%；距MA20 ≤8% |
| `risk-qualified` | 信号时已成熟的次日历史证据通过原推荐门槛，无证据则空仓 |

比较中包含未决的全部入场样本作为分母，分别保存次日触达笔数和比例。任何单笔超限先判风险不达标；无完成或存在未决判风险待核实；不足30个完整信号日、30笔完成交易或触达证据不全判证据不足。通过这些门槛，且信号日分块 bootstrap 的平均净收益下界大于0后，区分“目标未达到”“仅2.5%档观察达标”“两档观察达标”。80%仅是开发期的观察比例，不是预测概率；不能凭5笔中的4笔成功认定达标，也不能因成功率高忽略亏损。候选须冻结后另行验证最终区间，多次筛选后的最佳开发结果不能替代独立验证。

实验期限覆盖记录在 `spec.next_day_rule` 和 `result.development.research.parameters.max_holding_days=1`；快照原参数和原留出边界不变。由旧实验启动次日基线时，新记录成为自己的根基线；旧父档案仍可追溯。次日实验与原5日期限记录不显示数值提升差值，旧高点证据可派生“次日触达率”，但不能当成次日退出策略收益。引擎升级为 `indicator_selection_v7`：条件实验先按固定信号规则确定合格池，再在合格池内计算五日相对强度和机会评分，最后取 Top N；被规则移除的原全池 Top N 只保留审计证据，不参与评分或补位。不同引擎记录不显示提升差值；存储仍是向后兼容的 schema 1，旧记录缺失的逐笔触达证据明确显示未知，不改写原记录。

## 页面与指标

`/experiments` 提供最近 200 条记录的搜索和状态筛选，详情 URL 的 `id` 可收藏。根基线与父实验通过完整 ID 读取，不受列表数量限制；「后续实验」仅显示最近 200 条中已加载的子记录。

- 实验说明：运行状态与结论分开，展示预先记录的假设、变量和判定条件。
- 效果对比：根基线、父实验、本轮及变化量；仅在数据快照、引擎、代码版本、入场方式、期限和信号区间一致且双方成功时比较。
- 发现与缺点：计算事实、适用局限和待验证推断分别标记，亏损样本可以打开固定快照中的 K 线。
- 分组与样本：按月、行业和股票查看已完成、未决、盈利比例及最差单笔；可查看本轮入选和被过滤的原 Top N。被过滤样本的收益是同一成交模型的假设结果，不计入本轮业绩。
- 下一步：记录尚未回答的问题，并导航到后续实验。

条件低吸的固定信号规则先确定当日合格池，再只在合格池内计算五日相对强度和机会评分并取 Top N；被排除股票不会改变池内均值、排名或名额。`baseline` 的空规则不排除任何候选，因此保持原全池排序。原全池 Top N 中被过滤的样本仍记录排名和特征，仅供归因，不参与本轮评分或补选。`risk-qualified` 先要求信号日当时的已完成训练证据满足推荐门槛，包含亏损严格低于 3%、没有未决及最低样本要求，之后才取 Top N；无合格候选时空仓，不根据该笔未来收益删除亏损交易。费用、预算和持仓参数沿用固定快照。指标是重叠信号的单笔模拟统计，不是资金组合收益；页面不报告账户年化或组合最大回撤。

原持仓期限实验的通用验收如下；次日实验在上述独立目标下评估：

1. **硬条件**：每笔已完成交易的净亏损严格低于买入总成本的 3%，包含手续费、税费与成交滑点，等于 3% 也判超限。存在超限则为「风险不达标」；无完成交易或有未决则为「风险待核实」，不能用空仓或未知结果宣称安全。
2. 至少 30 笔完成交易和 30 个完整信号日期才能作为候选证据；信号槽位不足按现金 0，未知结果使该信号日不完整。
3. **软目标**：可卖出持仓窗口内最高价扣除费用及卖出滑点后，触达 ≥2.5%／≥3% 的比例越高、首次触达平均天数越短越好；不要求收盘价或实际退出收益达标。触达率分母为所有入场样本，包含未决；首次触达均值只计算触达目标的样本。实际净收益与实际平均持仓另列，避免把触达机会当作成交盈利。风险达标后，软指标至少一项改善且其他项不恶化时标「开发候选」；软指标互有升降标「收益／周期有取舍」。当前轮通过风险而父轮未通过时，优先记录风险改善，但仍要求当前平均净收益为正。达成率与周期不能抵消超限，不把 2.5% 或 3% 作为盈利上限。

止损模型保留 v3 的成本预留约束：向上取整触发价，并预留内置卖出滑点与成交分位取整；正常触发情况下，预计净亏损严格小于 `max(stop_net_pct, -3)` 的亏损边界。`plan` 输出 `net_loss_limit_pct`、`effective_stop_goal_net_pct`、`modeled_stop_net_pct`，实际成本无足够止损空间则拒绝计划。跳空按观察到的开盘及滑点执行，无法卖出仍保留为未决，**不把超限亏损裁剪成 -3%**。更紧的止损继续生效，更宽的内置参数不能放宽硬条件。

硬条件约束的是已完成模拟交易的最终净亏损。整根日线的 MAE 另行展示，可能包含平仓之后的价格，不能作为精确的盘中持仓回撤。历史零超限也不能保证未来实盘零超限；本系统是研究与提醒工具，没有自动向券商提交止损单。[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)中的交收及交易限制，和跳空/流动性限制，均会影响实际退出。

观察窗口自买入后的第一个可卖出交易日开始，至模拟退出或持仓期限；买入当天与退出后的交易日不计入。已知开盘退出时只观察开盘价格。日内退出仍保留该日最高价，若触达可能发生在退出后，标记每个目标的顺序未知以及 `exit_day_order_unknown`；该目标不计入已确认触达率及首次触达均值，不据此改写保守成交结果。停牌、缺失、除权等未知样本单独计数，不视为有效失败或成功。`Outcome.high_touch` 使用独立 `schema_version: 1`，记录两个目标的首次触达日、可观察天数和最高潜在净收益；旧档案缺少该对象时前端显示待核实，需要在新引擎重跑，不从旧 MFE 推测日期。

原档案及原结论不会重写。只读 API 的 `current_review` 按当前风险口径复核：列表从原统计检查最差单笔，旧档案不能提供精确超限笔数时显示「至少」；详情从保存的逐笔结果精确汇总，除权等未决结果不冒充已完成盈亏。数据不全时保持待核实。旧版“开发候选”若风险超限，当前界面优先显示“风险不达标”，同时保留原结论说明；新引擎需重新跑基线，禁止与旧引擎直接显示改善量。


## 数据范围与验证边界

行情读取通过一次 SQLite 事务获得复权/原始配对。元数据不合法、缺失或日期不一致的股票不参与，并保留排除原因。原始历史裁剪到前复权窗口，快照摘要包含数据内容、来源、股池、日历及参数的 SHA-256；读回时校验摘要。只保存行情与研究参数，不保存 webhook、Token 或其他配置凭证。

至少需要 60 根日线形成特征，再用有交易日历覆盖的日期训练和验证。不指定区间的日线实验中，最后 `strategy.holdout_days` 个可形成完整标签的信号日期作为保留区间，直至快照截止日都不评价；开发样本的完整持仓窗口触碰保留边界时会剔除。每天只能使用当时已经完整结束的标签作为训练证据。

十年原始数据的保存要求与可回测范围不同。复权窗口、交易日历、缺失股票或上市时间都可能缩短实验区间。当前股池并非历史逐日股池，存在存活和选择偏差；前复权数据是当前供应商快照，历史价格和行业分类不等于逐时点历史数据库。涨跌停、停牌、除权及日内触价先后仍受既有日线模拟约束。下一轮需要根据分组和个股证据提出独立假设；反复筛选相同开发数据不构成最终有效性证明。

历史 ST 状态与上市初期无涨跌幅限制窗口无法从现有行情中恢复，所有研究结果都会标记 `historical_st_unknown`。因此涨跌停成交假设只能视为近似，不能把该标记下的回测收益当成可直接复制的实际成交结果。

## 存储、接口与运维

独立 `experiments.db` 使用 schema version 1，UTF-8 JSON 保存快照和记录，单文档限 32 MiB；`calendar.db` 单独保存版本化交易日历窗口，不修改 `market.db`。两者沿用已有 CIFS 校验、软链接防护及 SQLite DELETE journal/FULL 同步方式；网页在库不存在时展示空档案，不创建数据库。备份时应暂停实验/日历写入再复制 `experiments.db` 与 `calendar.db`，不要单独复制正在写入的库文件。

所有接口仅接受 `GET/HEAD`，不提供写入入口：

| 地址 | 内容 |
| --- | --- |
| `/api/experiments` | 最近 200 条摘要，`schema_version: 1` |
| `/api/experiments?id=<完整ID>` | 固定实验记录与结果 |
| `/api/experiment-history?id=<完整ID>&code=<代码>&date=<信号日>` | 该实验已记录样本附近的不复权日线 |

无效参数返回 400、不存在返回 404、读取失败返回 503、超时返回 504；请求最多等待 5 秒，浏览器另有 10 秒时限。页面提供恢复入口，切换实验会取消旧请求并清除旧证据。API 使用 `Cache-Control: no-store`，嵌入静态资源使用 `no-cache`。

访问模型沿用现有本机只读看板，没有内置登录或管理员权限。远程部署应继续使用既有网关认证，并透传 `/experiments`、`/api/`、`/assets/`；网关拒绝访问时页面显示授权错误。部署新版本后进入 `/experiments`，核对代码版本、真实档案、K 线证据、失败状态及资源响应。仅构建或推送代码不会更新正在运行的页面。

验证入口：`make test`、`make vet`、`make dashboard-smoke`、`make docker-dashboard-smoke`。浏览器冒烟使用同一 `run` 启动模式和真实 SQLite，小数据集配合阻断的行情上游，覆盖空库、运行结果、父子导航、对比、冻结 K 线、移动端、网关拒绝、异常、超时与取消；不访问真实行情或通知服务。

逐轮实验结论、底部研究和行业对照记录仅保留在本地研究目录，不随仓库发布；生产行为、复现方法和可追溯档案格式以本文及[算法接入契约](algorithm-interface.md)为准。
