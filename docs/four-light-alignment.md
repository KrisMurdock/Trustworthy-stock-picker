# 近似四灯与目标软件对齐验收

## 目标

`four_light_approx_v1` 是本仓库基于价量特征计算的**近似实现**，不是约牛、高能智投或其他商业软件的公开原版公式。当前验收目标不是收益、胜率或止损，而是：**在相同股票、日期、周期和复权口径下，本地近似灯色是否与目标软件一致，首次全红和退出全红是否发生在同一根 K 线。**

公开资料可以确认约牛的“四维共振”涉及趋势、量能和多空状态，但没有公开四盏灯逐行计算公式。因此“趋势 / 量能 / 中期 / 短期”与具体软件的对应关系、参数、盘中处理和历史修订规则都必须在取得目标软件说明或连续灯色样本后核实。没有这些证据时，只能称为近似实现。

当前 `four_light_approx_v1` 的精确口径如下，只能按这四条解释红灯，不能按名称推断为原软件的“多方能量占优”等含义：

| 灯 | 当前近似规则 | 红灯含义 |
| --- | --- | --- |
| 趋势 | 收盘价高于 MA20 | 价格位于 20 日均线上方 |
| 量能 | 当日成交量达到前五日均量的 1.2 倍 | 仅表示放量；放量下跌也可能亮红 |
| 中期 | 收盘价高于 MA60 | 价格位于 60 日均线上方 |
| 短期 | 收盘价高于 MA5，且五日涨幅为正 | 短期价格与五日涨跌同时偏强 |

这些规则是待对照的基线，不因后续收益结果调整。需要修改公式时，应增加新的近似规则版本，不能让同一版本在不同实验中改变含义。

## 参考对象与采样顺序

1. 冻结当前 `four_light_approx_v1`，先修正对照工具和验收口径，不根据收益结果调参。
2. 明确目标软件、指标名称、软件版本、周期、复权设置和盘中/收盘处理方式。
3. 先用一只股票确认截图或录屏中的灯色能正确转录并跑通对照流程。
4. 再用不同股票、不同时间段，以及混合灯色、反复变色和失败行情检验稳定性。
5. 根据逐灯分歧研究目标公式；最后才扩展全市场，并单独讨论选股用途。

CSV 是工具输入，不是资料收集的前置门槛。截图、录屏和官方教学材料可以先用于确认指标含义，再转录为 CSV。一只股票只能验证流程，不能证明算法已经对齐。

## 两条独立验收线

| 层次 | 验收内容 | 当前状态 |
| --- | --- | --- |
| 四灯对齐 | 目标软件版本、四行名称、周期、复权口径、逐灯颜色、首次全红、持续全红、退出全红 | 未有目标软件连续样本，未对齐 |
| 选股与收益 | 四灯状态是否辅助选股，以及后续收益、风险和成交可执行性 | 独立研究，不能反向决定四灯公式 |

仓库原有的 `+3%` 净目标、`-3%` 止损和最长 5 日持有属于另一套交易模拟，不是四灯计算或对齐验收标准。

## 全市场独立归档

第一阶段的全市场链路是：

```text
sync-all → all-market.db qfq 日线 → four-light-all
         → 每日灯色与生命周期 → /four-light 与只读 API
```

`four-light-all` 不依赖候选排名，也不读取 `market.db`。它要求信号日是已完成的受覆盖交易日，信号日和上一交易日都有完整日线，且至少满足 60 根预热；否则保留明确的 `unknown` 或 `partial`。每只股票只记录一个生命周期状态：`first_all_red`、`continuing_all_red`、`exit_all_red`、`non_all_red` 或 `unknown`。当前或上一交易日无法判断时，不得产生首次或退出事件。

`all-market.db` schema 2 保存运行记录、每日状态和事件档案。成功重跑按 `(as_of, rule)` 在事务中替换该日全部记录；失败重跑不改写上次成功快照。网页 `/four-light` 展示当日汇总、首次/持续/退出全红、无法判断原因和个股历史；数据不足只显示 `unknown`，不能被展示成退出。归档只说明四条自定义价量条件及其历史状态，不代表选股有效，也没有接入正式推荐、通知或自动交易。

## 对照样本

参考样本必须来自明确的目标软件和版本，并满足以下条件：

- 使用同一股票代码、交易日、日线周期和前复权口径。
- 每个股票提供连续交易日灯色；缺失交易日必须说明原因。
- 至少覆盖 60 根日线预热，并包含首次全红前一根有效 K 线。
- 同时包含混合灯色、反复变色、持续全红、退出全红和失败行情，不能只截取上涨案例。
- 记录样本来源、导出方式、软件版本和是否存在盘中临时变色。

CSV 表头至少包含：

```text
code,date,trend,energy,mid_term,short_term
sz000001,2026-05-06,red,green,red,red
sz000001,2026-05-07,red,red,red,red
```

灯色接受 `red/green/unknown`，也接受 `红/绿/未知`。`unknown` 不进入一致率分母，不会被当成红色或绿色。额外列会被忽略；重复代码/日期、非法颜色和非连续交易日会被拒绝。

## 运行对照

```bash
go build -trimpath -o bin/four-light-align ./cmd/four-light-align

./bin/four-light-align \
  -data-dir /path/to/data \
  -reference /path/to/target-lights.csv \
  -software '目标软件名称' \
  -software-version '目标软件版本' \
  -period daily \
  -adjust qfq
```

工具只读 `market.db` 中已完成的前复权日线，不写行情、不生成报告、不发送通知。输出 JSON 包含：

- 报告 `schema_version: 2` 和 `event_pair_window_rows: 3`；
- 每盏灯的比较数、一致数、一致率和双方 `unknown` 数；
- 当前四灯全红状态的一致率；
- 首次全红、退出全红的命中、漏报、误报和 `unknown`；
- 转换提前或滞后的 K 线根数：负数表示近似实现更早，正数表示更晚；
- 转换事件先按同日配对；其余事件在 `±3` 根日 K 内按时间顺序做一对一最优配对，先保证匹配数量最多，再保证总偏移最小；超出窗口的剩余目标事件记为漏报，剩余近似事件记为误报，已配对事件不会复用；
- 逐灯分歧明细和样本质量警告；
- 目标软件版本、参考文件 SHA256 和数据来源。

`±3` 只是分析提前/滞后的配对窗口。只有同一根 K 线双方都发生转换才计入 `exact`（同日命中）；在窗口内配成的 `shifted` 事件仍属于对齐差异，只报告偏移根数，不能计入同日命中或一致率分子。

参考样本超出本地已保存的前复权窗口时，缺失日期会被拒绝，不会用不复权价格补造或跨来源拼接。需要三年或更长样本时，应先按生产口径补齐全窗口前复权行情，再冻结后比较。

当前工具只支持日线前复权，这是工具限制，不代表目标软件必须使用日线前复权；若目标软件口径不同，应先修改工具或明确差异，不能要求原软件迁就当前实现。

## 当前结论

当前没有目标软件连续灯色样本，也没有公开公式，因此：

- 不能宣称 `four_light_approx_v1` 与任何商业软件对齐；
- 不能用后续收益回测证明灯色公式正确；
- 不能把“四灯全红”表述为确定买点；
- 网页和实验报告只能展示“近似四灯 / 未对齐目标软件 / 仅观察”。

取得样本后，先报告逐灯一致率和转换差异，再讨论是否调整公式。任何阈值或参数调整都必须保留原规则版本，并在独立样本上复核，不能根据同一批对照结果反复调参后宣称对齐。
